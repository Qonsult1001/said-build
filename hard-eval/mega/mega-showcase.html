The "wall" was never scale — it was 3.5 GB of JSON data dumps. The original SAID-ECHO timeout (>20 min / 2,696 MB) predated the finding-#8 JSON-skip fix. Re-run with the fixed binary: the tree has 345,457 files, but is_junk_dir + the #8 .json skip drop it to 41,002 enrollable source files — because SAID-ECHO carries 3,502 MB of JSON, dominated by a single 2.6 GB longmemeval_m_cleaned.json benchmark dump (+265 MB, +245 MB more). Empirical answer: the ceiling was a data-dump artifact, not a project size. With #8, a 41k-source-file / 88k-frame project ingests at ~1.5 GB RAM.

* honest finding — init dir-append re-encodes the WHOLE brain (O(total), not O(new)). Growing a brain by appending directories one-by-one is not incremental: each said init <dir> re-runs the phase-2 encode over the entire accumulated brain, so it slows as the brain grows — measured: appending Advisory (72 files, +1,229 frames) onto a 90k-frame brain took ~7 min, of which 190 s was re-encoding the existing 90k frames, not the 1.2k new ones. The finding-#11 fix made learn_fix/remember single-frame writes incremental, but it does not cover the init directory path. Mitigation used here: a single one-shot init over all 12 codebases encodes everything once (the numbers above) instead of 12 compounding re-encodes. Research-correct A/B axes — pass@k · pass^k · Cost-of-Pass (doc 23)

The convergence methodology from doc 23 (grounded in pass@k 2107.03374, pass^k 2406.12045, Cost-of-Pass 2504.13359): 2 arms × tasks × n≥5 samples, INVALID runs excluded, partitioned into memory-only-solves / co-solved / abstention. Cost-of-Pass = (mean cost over all valid samples)/R amortizes failed attempts — the honest "how much to converge, not did-it-once" claim. Finding #11 was the most valuable result of the whole run — and it's now fixed. The incremental write path was always there and correct; it was being bypassed because the "is this a pure append?" check demanded every prior frame still be active, which a single tombstone (routine) broke. Relaxing it to tolerate tombstoned priors (harmless — inactive, filtered at query) restores the O(new) path: a write at 36.5k frames dropped from >2 min to 21.5 s (8.7k: 4 s). Only massive multi-project scale — where tombstones accumulate — surfaced this.
