# 14.12 — Crystalline annealing  (HORIZON)

> **Status:** designed, unshipped. Requires periodic eigendecomposition + fingerprint re-rotation.
> Roadmap entry: [Most elegant horizon item — crystalline annealing](../12-roadmap.md).
> The name aligns with **SCA** = Said Crystalline Attention — the retrieval engine's original name.

## Plain-English

Every N writes, we compute the eigenvectors of $\mathbf{S}_{\text{slow}}$ and rotate the fingerprint basis to align with them. Existing fingerprints are rotated by the same orthogonal transform (cheap — one 64×64 matrix multiply per frame). The embedding space **self-organises** around the corpus's principal axes as it grows, so fingerprint quality improves with corpus size rather than degrading.

No shipping memory system updates its representation space after ingest. We would.

## Formal statement

Let $\mathbf{S}_{\text{slow}} = U \Lambda U^\top$ be the eigendecomposition, with $U$ orthogonal and $\Lambda$ diagonal in descending order.

**Re-alignment step.** Every $N_{\text{anneal}} = 10{,}000$ writes (or on dream fire — see [14.5](14.5-auto-dream.md)):

1. Compute $U, \Lambda$ via QR algorithm. Cost: $O(64^3) \approx 260{,}000$ flops, sub-millisecond.
2. For every stored fingerprint $F(d) \in \{0,1\}^{64}$, compute the rotation:

$$F'(d) \;=\; \operatorname{sign}\!\big(U^\top \cdot \operatorname{unsign}(F(d))\big)$$

where $\operatorname{unsign}(b_i) = 2b_i - 1 \in \{-1, +1\}$.

3. Replace $\mathbf{S}_{\text{slow}} \leftarrow U^\top \mathbf{S}_{\text{slow}} U = \Lambda$ (diagonalised — subsequent updates accumulate in the aligned basis).

4. Record an `anneal:<timestamp>` audit entry with $U$'s checksum.

**Invariant maintained.** Pairwise Hamming distances between fingerprints are approximately preserved under the rotation — up to the $\operatorname{sign}$-flip on rotated coordinates close to zero. Quantitatively, expected Hamming change per document per anneal: $\mathcal{O}(\sqrt{n})$ bits (the $n$ dimensions where signs change under orthogonal rotation).

## Proof sketch (variance preservation)

**Claim.** Hamming distance between any two documents' fingerprints $F_1, F_2$ before and after annealing satisfies $|d_H(F'_1, F'_2) - d_H(F_1, F_2)| \le \mathcal{O}(\sqrt{n})$ with high probability.

*Sketch:* An orthogonal rotation preserves inner products exactly in continuous space. The sign function is 1-Lipschitz on a set of full measure but has discontinuities on coordinate hyperplanes. For a unit vector, the expected number of coordinates within $\varepsilon$ of zero after rotation is $\mathcal{O}(n \cdot \varepsilon)$; sign-flips on these coordinates contribute at most $\mathcal{O}(\sqrt{n})$ to Hamming distance in expectation. Therefore the retrieval-relevant distances change by a bounded, sub-linear amount — much smaller than typical between-document Hamming distances (20-32 bits on relevant pairs).

**Claim (self-improvement).** After annealing, $\mathbf{S}_{\text{slow}}$ is diagonal. Subsequent writes accumulate in a basis aligned with the corpus's principal axes. The first 16 or 32 fingerprint bits now carry the high-variance (high-information) structure, and Matryoshka truncation to 16 / 32 bits becomes valid for a shrunken-basis retrieval mode — opening the door to compressed on-disk storage.

## Implementation notes

- Eigendecomposition: QR algorithm in pure Rust, or linking `nalgebra` / `faer`. 64×64 is small enough that allocation dominates; keep state on stack.
- Fingerprint rotation: packed u64 → u64 with SIMD-friendly bit-unpacking. Cost per frame: 64×64 f32 matrix-vector multiply + sign pack = ~20k flops. At 1M frames: 2 × 10^10 flops ≈ 10 seconds on a modern core. Not hot-path; runs at anneal time only.
- Rotation matrix storage: add to the brain's header section (alongside `MODE`). Each anneal replaces it atomically.

## Expected impact

- Fingerprint quality improves with corpus size. Specific benchmark lift hard to predict — depends on corpus structure. Most likely wins:
  - **Large brains** (100k+ frames): cumulative fingerprint drift eliminated.
  - **Narrow-topic brains**: high-variance axes are the topic axes, so fingerprint quality compounds.
- Possibly enables **8-bit or 16-bit fingerprints** as a compressed retrieval mode (Matryoshka-valid in the re-aligned basis).

## Implementation cost

- ~500 lines Rust (eigendecomposition + rotation pipeline + audit entry).
- One-time migration path for existing brains. Recommendation: opt-in via `said admin anneal` command.
- ~1 week of focused work.

## Risks

- **Rotation drift under successive anneals.** If the corpus changes distribution repeatedly, the stored rotation matrices compound. Need to normalise or checkpoint; easy fix.
- **Audit complexity.** Annealing changes every fingerprint, so the audit log gets noisy. Mitigation: represent as one entry per anneal with a batch hash, not one per frame.
- **Immutability concerns.** Enterprises may require that stored fingerprints never change (legal archive semantics). For those brains, annealing is opt-out (or outright forbidden by `BrainMode::LegalArchive`).
- **Backward query compatibility.** A cached query fingerprint from before the anneal is invalid afterwards. Mitigation: invalidate any query embedding cache on anneal; queries are cheap to re-encode (0.08 ms).

## Literature positioning

- **Related**: online PCA (Warmuth & Kuzmin, 2008), incremental dimensionality reduction (Brand, *Incremental Singular Value Decomposition*, 2002), rotated bitvector indexes (Saad et al., 2018), adaptive hashing (Guo et al., *Quantization based Fast Inner Product Search*, 2016).
- **Distinctly different**: all of the above treat the re-basing as a batch precomputation. Crystalline annealing makes it a **streaming maintenance pass** in a retrieval system, interleaved with ingest and dream cycles.
- **Publishable claim**: periodic eigenbasis re-alignment of sign-bit fingerprints preserves Hamming retrieval quality in expectation while enabling compressed (low-bit) truncated retrieval modes via Matryoshka-valid truncation in the aligned basis.
