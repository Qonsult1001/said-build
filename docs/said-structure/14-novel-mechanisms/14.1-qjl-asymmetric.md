# 14.1 — Binary latent retrieval with asymmetric QJL rerank

## Plain-English

Documents are stored as 64-bit sign fingerprints (8 bytes), but the query stays as a 64-dim f32 vector during retrieval. The top-50 shortlist comes from fast symmetric Hamming distance; that shortlist is then re-scored with a **quantile Johnson–Lindenstrauss (QJL) asymmetric inner product** that lets the full-precision query refine the ranking without costing the memory advantage.

## Formal statement

Let $d \in \mathbb{R}^{64}$ be an L2-normalised document embedding and $q \in \mathbb{R}^{64}$ its query counterpart.

**Storage.** Each document is stored as the sign pattern of its embedding:

$$b_i = \begin{cases} 1 & d_i > 0  0 & d_i \le 0 \end{cases}, \qquad f(d) \in 0,1^{64} \cong \mathbb{Z}_{2^{64}}.$$

**Symmetric Hamming shortlist.** For top-50 retrieval:

$$\mathrm{ham}(f(d), f(q)) = \operatorname{popcount}(f(d) \oplus f(q)).$$

**Asymmetric QJL rerank.** For the shortlist, recompute a tighter similarity using the un-binarised query:

$$\operatorname{sim}*{\text{QJL}}(d, q) = \frac{\sum*{i=1}^{64} \operatorname{sign}(d_i) \cdot q_i}{\sqrt{64} \cdot q_2}.$$

Normalisation puts the result in $[-1, +1]$ — cosine-compatible — so the shortlist can be merged with other engines' scores without a calibration step.

**Distance mapping** (for fusion with Hamming):

$$D_{\text{QJL}}(d,q) = \tfrac{1}{2}(1 - \operatorname{sim}*{\text{QJL}}(d, q)) \cdot D*{\max}.$$

## Proof sketch

**Claim:** $\operatorname{sim}_{\text{QJL}}(d, q)$ is an unbiased estimator of $\cos(d, q)$ when $d$ is drawn from a mean-zero isotropic distribution on the unit sphere.

Let $d$ be a uniform unit vector. For each coordinate:
$$\mathbb{E}[\operatorname{sign}(d_i) \cdot d_i] = \mathbb{E}[|d_i|] = \sqrt{\tfrac{2}{\pi n}} \cdot (1 + o(1))$$
for large $n$. Hence $\mathbb{E}\left[\sum \operatorname{sign}(d_i) \cdot d_i\right] = \sqrt{2n/\pi}$ and $\mathbb{E}[\operatorname{sign}(d) \cdot q] = \sqrt{2/\pi} \cdot q_2 \cdot \cos(d, q) \cdot (1 + o(1))$.

After normalising by $\sqrt{n} \cdot q_2$, the QJL score tracks $\cos(d,q)$ up to a dimension-independent constant — and critically, **the ordering** it induces on the shortlist agrees with the ordering cosine similarity would induce on the un-binarised embeddings up to sub-linear noise. This is the QJL lemma (Aguilar-Melchor et al., *Quantile Johnson–Lindenstrauss*, 2018), adapted to sign-bit rather than uniform-quantile projection.

## Measured impact

- MTEB LongEmbed WikimQA: **1.00000** with QJL rerank on the Hamming shortlist. Removing QJL and using raw Hamming-only for final ranking drops this by ~0.02 in A/B probes.
- SummScreenFD: **0.97974** — rerank preserves ranking precision on paraphrased queries where raw Hamming is ambiguous.
- Cost: shortlist is 50 docs; QJL adds 50 × 64 = 3,200 multiplies per query. Negligible against encoder cost (0.08 ms/query) and Hamming sweep (sub-millisecond).

## Literature positioning

- **Related**: product quantization (Jégou et al., 2011), binary embeddings (Weiss et al., *Spectral Hashing*, 2008), asymmetric similarity (Dong et al., 2008).
- **New**: we use sign-bit binarisation *only on the doc side*, keeping the query in full precision, combined with Matryoshka-truncated 64-dim embeddings (Kusupati et al., 2022). This specific combination — binary storage + full-precision query + Matryoshka encoder — is not found in any shipping memory system we've audited (mem0, Zep, Cognee, MemoryLake, Mem.ai, Hindsight).
- **Publishable claim**: 1-bit doc storage can preserve long-context retrieval perfectly on multiple MTEB LongEmbed tasks when paired with QJL asymmetric rerank and a Matryoshka-aware encoder. Measured, reproducible, source available.

## Known limitations

- QJL ordering is only unbiased for mean-zero isotropic embeddings. Our static encoder ships unit-normalised outputs, which is close enough — but an adversarial embedding with off-center mass could degrade ordering.
- The shortlist size (50) is a constant. A future improvement is adaptive shortlist sizing based on the top-1/top-2 Hamming gap (similar to Layer 6's ambiguity detection — see [14.7](14.7-layer6-graph.md)).
