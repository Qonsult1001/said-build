# 14.15 — Canon memory (the 80/20 split, stored once, rendered per language)

The highest-leverage form of `.said`'s owned memory: store the **80% framework canon** — the byte-identical
*shape* that repeats across every entity/project — **once, language-neutral**, and at recall **guide the
LLM to render it in the active language**, so the agent regenerates the 80% for free and authors only the
20% delta. One canon → every language. Not a per-language/per-architecture catalogue.

## The idea (from the said-cgp-cs 80/20 split)

Real codebases are ~80% **framework canon** + ~20% **entity-specific content**
(`SAID-ECHO/said-cgp-cs/docs/80-20-split.md`). For a `Create<Entity>` endpoint the 80% — request
signature, audit pipeline, error-envelope CATCH, the OPENJSON shred *pattern*, the response wrap — is
identical across Account / BinSponsor / 3DSecure / your-next-app. Only 6 slots change (the fields, the
DML, the children, the response projection, the business guards). A `calculate-interest` function is the
same: the *scaffold* around it (validate → compute → guard → return) recurs; only the formula is new.

**`.said` should remember the 80%, not just past fixes.** Then every new entity costs the agent only the
20% — the 80% is never re-derived or re-tokenized.

## Why NOT a per-language catalogue (the owner's constraint)

`said-cgp-cs` stores the canon per `(architecture × host × language)` — a real catalogue. That does not
scale to "global portable memory." `.said` must do it the way it already does fix-recall: store the
**learning/intent ONCE** and **guide the engine** to the right concrete answer for whatever language is
active — exactly how `recall_fix` stores the invariant (not the per-language diff) and `SAID_RECALL_LANG`
guides to the active language.

## The representation — decided by research (structured NL, not a formal IR)

Research is decisive on what an LLM renders reliably across languages:

- **No universal formal IR exists** — *"natural language consistently emerges as the most effective
  intermediate representation across all target languages; no universally effective intermediate formal
  language exists"* ([Assessing Code Generation with Intermediate Languages, arXiv:2407.05411]). ⇒ a
  formal IR is the WRONG canon format.
- **Structured natural language beats pseudocode** — decompose into ordered *phases* in NL, then render
  ([Structured Chain-of-Thought Prompting, TOSEM 2025]). ⇒ canon = ordered NL phases.
- **Model-authored specs render most reliably** — let the LLM phrase the canon in its own vocabulary
  ([Self-Spec, OpenReview 6pr7BUGkLp]). ⇒ don't impose a rigid schema it fights.

So a **canon frame** is language-neutral structured intent:

```
shape:   Create<Entity>            # the intent key — fingerprinted, like recall_fix's action residue
phases:  (ordered structured NL — the 80%)
  1. validate the request body is present
  2. shred the input fields from the request payload
  3. guard required fields → error envelope on missing
  4. write the primary row (the DML)
  5. write child rows if any
  6. project the response object (and wrap/return per the framework envelope)
slots:   [fields, dml-target, children, response-shape, business-rules]   # the 20%, named
guide:   render in the ACTIVE language/architecture; keep phase order; fill slots from the entity schema
```

## Recall = the existing engine, pointed at structure

This needs **no new retrieval mechanism** — it reuses what's proven:

| `recall_fix` (live) | canon recall |
|---|---|
| stores the invariant, not per-language code | stores the canon (phases+slots), not per-language code |
| intent/action fingerprint keys recall | the `shape` (Create/Update/GetById/Paginate/SubResource) is the intent key |
| `SAID_RECALL_LANG` guides to the active language | the active stack guides the LLM to render the canon there |
| LLM adapts, gate verifies | LLM renders the 80% + fills the 20%, gate verifies |

So: agent asks "Create endpoint for Invoice in `<stack>`" → `.said` recalls the **Create canon** (one,
global) → LLM renders the 80% in the target language and fills the 6 slots from Invoice's schema. The 80%
is regenerated from one stored canon, never re-tokenized.

## Why this is the moat (and frictionless)

- **Structural reuse, not lexical** — `Create` is `Create` across entities, projects, AND languages; the
  canon is reused every time that shape recurs, forever. This is the real 80/20 token story (skip
  re-emitting 80% of every file in every bundle), far bigger than "recall one function."
- **Owned, portable, compounding** — the canon set is `.said`'s asset; it grows as the agent verifies new
  shapes; it travels across models/machines as one file. A competitor can copy retrieval; they can't copy
  your accumulated canon.
- **Frictionless / not an obstacle** — `.said` is the canon layer *underneath* Claude/Kimi/Cursor: the
  host agent just gets a better, cheaper, more consistent answer (80% handed over; it spends tokens only
  on the 20%). `.said` makes the agent better, which is why they buy it instead of routing around it.

## Canon acquisition — born TWO ways (forward + harvested), dedup-by-shape

Canon enters the brain through two paths, so an existing `.said` + a fresh `init` is immediately
canon-rich instead of starting empty:

1. **Forward (as we work):** after a verified build, the agent records the canon for a shape it just
   implemented — same trigger as `learn_fix` on green.
2. **Harvested at `init` (retroactive):** when a project is `init`'d into an existing brain, `.said` reads
   ALL the existing code, detects recurring structural shapes (Create/Update/GetById/handler/…), and
   extracts a canon from the patterns already there. The codebase you already have becomes canon on day
   one — the 80% you've written a hundred times is captured automatically.

**Dedup by SHAPE (not by text):** if a canon for that shape already exists, **skip it and move on** — do
NOT store a second. The first canon for `Create` stands; later occurrences only *reinforce* it (recall
weight), they don't duplicate. This keeps the canon set small and authoritative (one canon per shape),
and is why harvesting a big existing codebase doesn't bloat the brain — N Create endpoints → ONE Create
canon. (Contrast `learn_fix`'s per-task identity; canon identity is the SHAPE alone.)

This is the best-of-both-worlds the owner asked for: new projects grow canon forward, and importing
existing code mines canon retroactively, with dedup keeping it to one-per-shape.

## Prototype result (2026-06-28) — thesis PROVEN + one design fix found

Prototyped on the live CLI (canon stored via the `learn_coding_fix` engine, tagged `canon:create`):
- **Store + recall by intent:** the canon (6 NL phases + named slots) stores and recalls; shape-phrased
  queries score 0.59–0.65 and the bare action "create" recalls at 0.61 via the action-residue fingerprint.
  **Recall-key finding:** canon must be keyed on the SHAPE/ACTION, not the entity noun — a distant
  noun-led paraphrase ("Invoice endpoint") scored only 0.18. An agent naturally queries by action
  ("create endpoint"), and storing the canon's problem as the bare shape makes this robust.
- **ONE canon → TWO languages (the headline, proven in physical code):** the same stored canon rendered
  into `dotnet` (`InvoiceController.cs`) and `rust/axum` (`invoice.rs`) — identical 6-phase 80% structure
  (accept → guard → INSERT → project), only the 20% slots (fields/DML/response) differ per language.
- **DEDUP FINDING (must fix for canon):** storing a 2nd Create kept the frame count flat (good, no
  pile-up) — BUT it did so by **last-write-wins supersede**, which OVERWROTE the good canon with the
  throwaway. Canon's rule is the OPPOSITE: **keep the existing canon, SKIP the new** ("if canon exists,
  don't dedup, move on"). So canon needs a **keep-first** dedup (first canon for a shape stands; later
  occurrences only reinforce recall-weight), NOT `learn_fix`'s supersede. This is the one engine change
  canon requires beyond the existing store.

## Marker convention v2 — header index + provenance classes (the "intent-driven, less-noise" fix)

Refinement (owner): intent-driven development should have FEWER inline comments but a RICHER header — a
`@said-managed` **section index** (OKF/wiki-style) so each region is referenced by a NUMBER, not verbose
per-line comments. Plus a marker for **where the AI added NEW code**, which makes a real metric possible:
*how much new code did the AI generate vs the framework/old system?*

Research backing: ~41% of code merged globally in 2025 was AI-assisted but carries **no structured
provenance record** ([nhimg.org/code-provenance]); the field's problem is **fragmentation** — "can't query
across repos because every repo uses a different schema or none" ([same]). There is **no dominant
numbered/indexed managed-region standard** (closest: `#region`, MDA/EMF protected regions, source-gen
marker attrs — all language-specific). So `.said` can define the ONE consistent, **language-agnostic,
indexed** convention the field lacks — which is exactly the "global" property canon needs (same markers in
C#, Rust, SQL, TS…).

**Header section index (declared ONCE; the body uses terse numbered anchors):**

```
// @said-managed: index  canon=Create<Entity>  lang=dotnet
//  §1 accept-and-audit   Fully    framework
//  §2 guards             Ignore   entity-20%
//  §3 dml                Ignore   entity-20%
//  §4 response           Ignore   entity-20%
//  §5 envelope+return    Fully    framework
// @said-managed: end
```
Body regions then collapse to `// §2` … `// §end` — no prose, just the indexed anchor (clean code,
trivial to recall/manage, and the index is the OKF-wiki for the file).

**Provenance classes (extends the said-cgp-cs Fully/Ignore with AI/Human):**

| Class | Meaning | Counts as |
|---|---|---|
| `Fully`  | framework canon, regenerated byte-identical | **framework** (free — `.said` regenerated it) |
| `Ignore` | entity-specific slot, agent/human fills, preserved on re-render | **entity 20%** |
| `AI`     | NET-NEW code the AI authored (not canon, not a slot) | **AI-net-new** |
| `Human`  | hand-edited outside any slot | **human** |

**The calculation it unlocks (the buy-worthy metric):** count lines per class →
`framework% / entity-slot% / AI-net-new% / human%`. So you can state, auditable:
> "Old system: human wrote 100%. With `.said` canon: framework regenerated **X%** for free; the AI authored
> only **Y%** net-new; the human touched **Z%**." — a real productivity + token-savings number, and the
> active code-provenance record the industry currently lacks. (Reference renders updated in
> `hard-eval/canon-proto/`.)

## Convention v2 fixes (rendering, ordering, global OKF map)

Three corrections from real use:

1. **ASCII anchors, not `§`.** The section sign `§` is U+00A7 (non-ASCII) and renders as mojibake across
   editors/terminals/OSes — fatal for a GLOBAL standard. Anchors are now pure ASCII `S1..SN` (body) +
   `index` block. All canon artifacts are verified **0 non-ASCII bytes**.
2. **`SN` = EXECUTION ORDER.** The earlier index listed sections in a static order the body didn't follow
   (the AI net-new block ran before the guards, but was numbered last). Anchors now match the body
   top-to-bottom, so the header index IS the file's flow map. Header carries
   `NOTE: SN = EXECUTION ORDER`.
3. **OKF reserved files = the GLOBAL map** (Google Open Knowledge Format: `index.md` catalog + `log.md`
   history; markdown + YAML frontmatter; only `type` required). `said.index.md` catalogs EVERY managed
   section across EVERY file as `file#SN`, so audit/recall map back globally — this is the "wiki that maps
   to files" the owner asked for and the cross-repo audit the provenance research says is missing.
   `said.log.md` is the change/provenance history. (Demo: `hard-eval/canon-proto/said.index.md` + `.log.md`.)

**The honest metric framing (owner's correction):** the framework 80% (`Fully`) was **AI-authored ONCE**;
its ongoing cost is ~0 because it's regenerated byte-identical. So the value is two distinct things:
- **Token savings** = the `Fully` regions re-emitted for free on every file/entity, forever (no re-reasoning).
- **The genuine hard work** = the `AI` net-new + `Ignore` entity-20% the agent must actually think through.
The OKF catalog makes this auditable per file: "X of N regions regenerated free; Y of N are the real work."

## Labels = EDIT-SAFETY (greenfield) + PROVENANCE (only when scanning old code)

The owner caught a real confusion: in a FRESH build the AI writes EVERYTHING, so "AI-added vs your code"
is meaningless there. The industry-proven model (Speakeasy custom code regions: "the generator OWNS
generated files; editing them is overwritten on the next run; custom regions are carried forward") labels
by **edit-safety**, not authorship. Two separate axes, used per scenario:

**Axis 1 -- EDIT-SAFETY (ALWAYS shown; the only thing a user must know to act):**

| Label | Meaning | What the user does |
|---|---|---|
| **GENERATED** | `.said` regenerates this; your edits get OVERWRITTEN | Don't edit here. To change it: edit the **canon/template** (updates everywhere), or **`said eject <Sn>`** to take ownership (it becomes YOURS). |
| **YOURS** | `.said` PRESERVES this across renders | Edit freely; carried forward (Speakeasy custom-region contract = said-cgp-cs `@said-managed: Ignore`). |

So "how do I control a GENERATED/LOCKED section?" -> don't fight it in the file; **edit the canon or
eject**. That answers the owner's control question.

**Axis 2 -- PROVENANCE (shown ONLY for scanned/brownfield code):** when `.said` ingests an EXISTING
codebase it CAN tell what was already there from what it added, so review is meaningful:
**WAS-YOURS** (pre-existing) vs **SAID-ADDED** (new -- review this). In greenfield this is omitted (all
AI; not useful) -- only edit-safety shows. The owner's "everything is AI / what about scanned old code"
question = exactly this: greenfield shows edit-safety; brownfield adds WAS-YOURS/SAID-ADDED for review.

**Control commands (the user's levers over GENERATED code):** `said eject <Sn>` (GENERATED -> YOURS);
edit the **canon** (one change updates every GENERATED instance); `said diff` (brownfield: WAS-YOURS vs
SAID-ADDED). Demonstrated labels in `hard-eval/canon-proto/` (greenfield: GENERATED/YOURS only).
