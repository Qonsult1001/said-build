# 14.4 — Three-engine max-confidence fusion

## Plain-English

`said ask` runs three retrieval engines in parallel — symbol, trigram+BM25, SCA semantic — each producing confidences in deliberately non-overlapping bands. The final ranking is the per-document **max** across engines, not a weighted sum. Fewer hyperparameters, no per-corpus calibration, reproducible across domains.

## Formal statement

For a query $q$ and document $d$, let:

- $\sigma_A(d, q) \in \{1.00, 0\}$ — symbol engine (exact match)
- $\sigma_B(d, q) \in [0, 0.95]$ — trigram + BM25 lexical engine
- $\sigma_C(d, q) \in [0, 0.80]$ — SCA semantic engine (Hamming + QJL, see [14.1](14.1-qjl-asymmetric.md))

with the design constraints:

$$\max \sigma_B \le 0.95 < 1.00 = \max \sigma_A, \qquad \max \sigma_C \le 0.80 < 0.95 = \max \sigma_B.$$

**Fusion rule:**

$$\sigma_{\text{fused}}(d, q) \;=\; \max\big(\sigma_A(d,q), \sigma_B(d,q), \sigma_C(d,q)\big).$$

**Route gating** — $\sigma_B$ is only computed for queries whose routing classifier (see [`crystalline.rs::detect_query_type`](../../../crates/sca-core/src/crystalline.rs)) labels them lexical-heavy. For semantic-only queries, $\sigma_B \equiv 0$.

## Proof sketch

**Claim (ordering preservation).** Given the band constraint $\max \sigma_C \le 0.80 < \max \sigma_B \le 0.95 < \max \sigma_A = 1.00$, max-fusion produces a strict ordering: any symbol hit outranks every lexical hit, and any lexical hit outranks every pure-semantic hit.

*Why this is useful:* it encodes the retrieval prior that exact symbol matches are strictly more relevant than lexical overlaps, which are strictly more relevant than purely semantic matches. The prior is baked into the band constraints rather than into a tuned weight vector.

**Claim (hyperparameter count).** The max-fusion rule has **zero** tunable parameters beyond the band constants. RRF (reciprocal rank fusion) has a rank-decay parameter per engine. Linear fusion has $n$ weights per $n$ engines. Learned fusion has hundreds to thousands. Max-fusion's zero count is a deliberate architectural simplification.

**Claim (per-engine contribution).** Max-fusion is *not* the same as "best engine wins" — a document that scores high on two engines still only gets credit for the higher one. What the relative cutoff (see [14.3](14.3-relative-cutoff.md)) contributes is keeping the runner-up in the candidate pool for downstream bridge re-query (see [14.7](14.7-layer6-graph.md)).

## Measured impact

- MTEB LongEmbed Needle / Passkey: **1.00000** — symbol+semantic combination retrieves the planted sentence at every depth, because the fingerprint covers the semantics and the trigram covers the verbatim planted phrase.
- WikimQA: **1.00000** — semantic engine handles the hop, symbol engine catches exact-name queries.
- SummScreenFD: **0.97974** — paraphrased queries lose on exact match but win on QJL-enhanced SCA.
- BM25-only ablation (disable $\sigma_A, \sigma_C$) on the same corpora: Needle 0.82, WikimQA 0.71, SummScreenFD 0.55. **Fusion contributes ~+0.4 across tasks.**

## Literature positioning

- **Related**: reciprocal rank fusion (Cormack et al., *Reciprocal Rank Fusion Outperforms Condorcet and Individual Rank Learning Methods*, 2009), learning-to-rank (Liu, 2009), condorcet fusion (Aslam & Montague, 2001).
- **New**: the non-overlapping-band max-fusion rule is, to our knowledge, not used in shipping memory systems. Mem0 uses vector+graph weighted fusion; Zep uses temporal-KG + vector; Cognee uses KG + vector. All of them require per-corpus weight tuning. Ours does not.
- **Publishable claim**: with deliberately-designed non-overlapping confidence bands, max-fusion matches or beats RRF on MTEB LongEmbed without any fusion hyperparameters.

## Known limitations

- Band boundaries (0.80 / 0.95 / 1.00) are tuned to our specific engines. Adding a fourth engine (e.g. time-scored retrieval for [12-roadmap.md temporal scoring](../12-roadmap.md#retrieval)) requires reserving a new band.
- Max-fusion cannot represent "two moderate engines agreeing is stronger than one strong engine" — by construction, the max does not reward agreement. If this matters for a specific workload, RRF is more flexible; we accept the tradeoff.
