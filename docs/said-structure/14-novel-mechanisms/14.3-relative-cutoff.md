# 14.3 — Relative-cutoff retrieval

## Plain-English

Instead of dropping results below a fixed score threshold (BM25's orthodoxy), we drop results below a fraction of the top-scoring result. A guaranteed-survival floor ensures the top-3 semantic hits always pass the cutoff even when a symbol or trigram hit dominates. Scale-invariant, parameter-light, resistant to score drift across corpora.

## Formal statement

Let $\mathcal{R} = \{r_1, r_2, \dots, r_k\}$ be the candidate result set with scores $s(r_1) \ge s(r_2) \ge \dots \ge s(r_k)$.

**Cutoff rule:**

$$\mathcal{R}_{\text{kept}} \;=\; \{r_i : s(r_i) \ge \alpha \cdot s(r_1)\} \;\cup\; \mathcal{G}$$

with $\alpha = 0.30$ and

$$\mathcal{G} = \{r : \operatorname{engine}(r) = \text{SCA},\; \operatorname{rank}_{\text{SCA}}(r) \le 3\}$$

— the top-3 SCA-engine results, guaranteed to survive.

## Proof sketch

**Claim 1 (scale invariance).** For any $\lambda > 0$, scaling all scores by $\lambda$ yields the same kept set. Direct: $s \mapsto \lambda s$, so $s(r_i) \ge \alpha s(r_1) \iff \lambda s(r_i) \ge \alpha \lambda s(r_1)$.

**Corollary:** cutoff behaviour does not depend on corpus size, encoder calibration, or score normalisation across engines — it only depends on the *relative* distribution of scores within a single query.

**Claim 2 (semantic-recall floor).** Any query has at least 3 SCA candidates returned (SCA retrieval returns a fixed top-50). $\mathcal{G}$ has cardinality $\ge 3$. Therefore $|\mathcal{R}_{\text{kept}}| \ge 3$ for every non-empty query.

## Measured impact

- On ambiguous queries (where top-1 and top-2 are within 10%), relative cutoff keeps 2-4 more relevant candidates than an absolute threshold would at the same false-positive rate. Measured via intent-miss diagnostics on `realworld_recall_probe`.
- On unambiguous queries (top-1 score > 0.9, runner-up < 0.3), relative cutoff drops noise that an absolute threshold at e.g. 0.2 would keep. Net effect on SummScreenFD: +0.003 NDCG@10.
- No hyperparameter tuning per corpus — $\alpha = 0.30$ and $|\mathcal{G}| = 3$ are fixed. Validated across Code / Episodic / Docs brains with no per-domain re-tuning needed.

## Literature positioning

- **Related**: BM25's threshold-based pruning (Robertson & Zaragoza, *The Probabilistic Relevance Framework*, 2009), learning-to-rank confidence calibration (Li, *Learning to Rank*, 2011), reciprocal rank fusion (Cormack et al., 2009).
- **New**: most retrieval systems cut on absolute scores (BM25's $k=1.2$ threshold tradition) or on fixed top-$k$. Relative cutoff with a semantic-floor guarantee is, to our knowledge, not used in any shipping memory system. It matters specifically for fused engines like SAID's (see [14.4](14.4-max-fusion.md)) where different engines produce scores on different scales.
- **Publishable claim**: scale-invariant cutoff with a typed-engine floor is a parameter-light alternative to score calibration for cross-engine fusion, and measurably improves precision on ambiguous queries without a per-corpus training step.

## Known limitations

- $\alpha = 0.30$ is static. Adaptive $\alpha$ based on the distribution variance of the candidate scores is on the horizon (see [12-roadmap.md retrieval](../12-roadmap.md#retrieval), dynamic cutoff item).
- The semantic floor size (3) is a magic number. It was set because it covers typical multi-hop bridge scenarios (see [14.7](14.7-layer6-graph.md)); a more principled choice would scale with query entropy.
