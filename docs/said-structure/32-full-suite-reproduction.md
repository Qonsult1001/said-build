# 32 — Full beat-them suite: exact reproduction (every step)

The complete end-to-end test that proves `.said` holds EVERYTHING in ONE portable brain and wins on every
documented axis ([30](30-beat-them-benchmark.md)). Built against the REAL on-disk Claude corpus + the whole
`.said` project. This doc is the runbook — every step, every script, every gotcha — so the suite is
reproducible byte-for-byte.

All scripts live in [`hard-eval/beat-them/`](../../hard-eval/beat-them/). The canonical brain is
`hard-eval/beat-them/claude-import/claude.said` (gitignored — it's a 7 MB build artifact, regenerated by
the steps below).

## What the suite proves (one brain, all kinds, all axes)

| Kind in the ONE `.said` | Count | Recall lane (use the RIGHT lane) |
|---|---|---|
| Code AST chunks | ~4,500 | `said ask` / `--pillar code` |
| **Symbols** (tree-sitter) | **3,391** | `said sym <name>` — EXACT, sub-ms |
| **Blueprints** (harvested + seed) | 186 + 4 | `said recall-blueprint --shape` |
| Coding fixes | seeds | `said recall-fix --problem` |
| Memories (claim+evidence) | 25 | `said memory-manifest` / `recall-memory --name` |
| Docs / planning | all | `said ask` / `--pillar semantic` |
| Git commits | 346 | `said ask` / `--pillar episodic` |

> **Gotcha #1 — use the right lane.** Blueprints recall via `recall-blueprint`, NOT `ask`. Memories recall
> via `recall-memory`/`memory-manifest`. Code via `sym`. Probing one kind with another's tool reads as a
> false miss — most of the early "failures" in building this suite were exactly this.

## Prerequisites

```bash
# Windows + Git Bash; node on PATH; the coding binary built:
cargo build -p said-cli -p said-mcp --no-default-features --features "coding"
# binary at target/debug/said.exe ; MCP at target/debug/said-mcp.exe
```

## STEP 1 — build the ONE complete brain

The brain must hold **everything** in one file. Build it the documented way (see the symbol-index rule in
[07-cli-reference/init.md](07-cli-reference/init.md)): a SINGLE full `init` over the code, NOT piecemeal
per-subdir inits (those rebuild the SYMS index for that run only and clobber the symbol table — measured
**7 symbols instead of 3,391**).

The reproducible path (proven; avoids the repo-root-init pitfall in Gotcha #2):

```bash
# 1a. Start from a full code/docs/git project brain built by ONE init pass.
#     (project-brain/project.said is such a brain: 5,009 frames, 3,391 symbols, OKF graph, all git commits.)
cp hard-eval/beat-them/project-brain/project.said hard-eval/beat-them/claude-import/claude.said
cp hard-eval/beat-them/project-brain/project.said.spill hard-eval/beat-them/claude-import/claude.said.spill 2>/dev/null || true

# 1b. Harvest blueprints from the code (now DEFAULT-ON in `said init`; here run standalone on an existing brain).
SAID_PROJECT=said-build ./target/debug/said.exe --path hard-eval/beat-them/claude-import/claude.said harvest crates
#   -> "Harvested 186 blueprint(s) from 337 files (3088 functions scanned)"  (SYMS preserved)

# 1c. APPEND the distilled Claude memories + seed fixes/blueprints (append, NOT a re-init — see Gotcha #3).
node hard-eval/beat-them/add-memories-to-brain.js
#   -> "added 25 Claude memory records + 2 blueprints + 2 fixes (via append, SYMS preserved)"
```

Verify the complete brain:

```bash
B=hard-eval/beat-them/claude-import/claude.said
./target/debug/said.exe --path $B stats --verbose | grep -E "Memories:|Symbol table"   # 5,340 mem, 3,391 syms
./target/debug/said.exe --path $B sym build_concept_links                                # EXACT hit
./target/debug/said.exe --path $B recall-blueprint --shape "Create<Entity> REST endpoint" --min-similarity 0.0
./target/debug/said.exe --path $B recall-fix --problem "build an LRU cache O(1)" --min-similarity 0.0
./target/debug/said.exe --path $B memory-manifest | head                                  # 25 records
```

> **Gotcha #2 — never `said init <repo-root>`.** Initting the whole repo root walks `target/` (GBs of
> build artifacts), `.git/`, and the brain's own output dir — it hangs / produces 0 frames. Init the
> SOURCE dirs (`crates`, `docs`), or use the project-brain copy above.

> **Gotcha #3 — APPEND, don't redo.** `build_index` is incremental-aware (doc
> [3.1](03-core-subsystems/3.1-sca-engine.md): O(new) against the persisted corpus mean; full rebuild only
> on >50% growth). Add memories/fixes/blueprints to an existing brain with `save-memory`/`learn-*` (append).
> Do NOT rebuild from scratch, and BATCH appends in one process where possible (running N separate `save-
> memory` CLI processes each re-opens + re-saves the 7 MB file — slow, the "redo across the board" trap).

### Alternative: rebuild from raw sources (heavier, fully from scratch)

- `node hard-eval/beat-them/import-claude-corpus.js` — distil Claude's 131 MB of transcripts into the
  doc-29 3 tiers (facts + ONE consolidated note per session + DROP raw), then init the whole project.
  (This path exercises harvest-on-init; slower.) See [29](29-learning-from-claude-kimi-memory.md).

> **Gotcha #4 — consolidation is per-(shape, SAID_PROJECT).** Keep-first dedups only when the SAME shape
> is re-learned under the SAME `SAID_PROJECT` (doc_id = `shape::blake3(shape+project)`). Re-learning under a
> different/empty project is a DIFFERENT blueprint by design — not a bug. The suite uses one isolated
> project for this axis. Proven: `learn-blueprint <shape>` twice under `SAID_PROJECT=x` → ONE blueprint,
> original sections kept, the 2nd (CLOBBER) rejected.

## The honest framing (what this suite does and does NOT claim)

- **Claims (measured):** ONE `.said` holds all kinds; each recalls via its lane; compaction-survival +
  token savings are real and large; code recall is EXACT by symbol/AST; keep-first consolidates per project.
- **Does NOT claim:** beating mem0 on fuzzy fact-recall@1 leaderboards (a single fixed-dim vector has a
  mathematical ceiling, arXiv:2508.21038 — see [31](31-memory-evidence-standard.md)). We compete on
  COMPOUNDING + COMPACTION-SURVIVAL, the unsolved frontier (arXiv:2602.01966), not fact-recall.
- Every "failure" encountered while building this suite was a HARNESS bug (wrong recall lane, inconsistent
  `SAID_PROJECT`, repo-root init, N-process append) — each diagnosed and fixed; the `.said` mechanisms
  themselves are correct.
