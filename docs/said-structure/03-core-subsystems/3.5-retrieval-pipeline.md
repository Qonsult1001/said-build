# 3.5 — Retrieval pipeline

The canonical `.said` recall path. Every `ask`, `search`, `recall` call — from CLI, MCP, or the Rust API — lands in this pipeline. Lives in [`crates/sca-core/src/recall.rs`](../../../crates/sca-core/src/recall.rs) and [`crates/sca-core/src/ask.rs`](../../../crates/sca-core/src/ask.rs).

Zero LLM. Pure deterministic layers. Every improvement is documented with the MTEB / LoCoMo delta it produced.

## Top-level entry points

```
said ask <query>            → cmd_ask (CLI)       → sca_core::ask::ask(brain, ...)
MCP ask                     → handle_ask (MCP)    → sca_core::ask::ask(brain, ...)
MCP search                  → handle_search       → brain.recall_by_pillar(...)
brain.recall(query, top_k)  → Rust API entry      → search_full_scoped(...)
```

All four funnel into `recall::search_full_scoped_pillars` for the actual work.

## Layer stack (in order)

### Layer 0 — query routing

`CrystallineCore::detect_query_type(query)` classifies the query into one of three routes:

- **PureLexical** (code/NIAH) — high-IDF tokens dominate, alpha 0.85
- **PureSemantic** (short paraphrase, low IDF, no high-IDF term) — alpha 0.00
- **FullHybrid** (intent queries) — alpha 0.70

The route gates whether BM25 + graph fan-out fire. `PureSemantic` skips them (paraphrase queries are worse with keyword boosts).

### Layer 1 — SCA top-50

```
sca_hits = engine.search_immutable(query_emb, query_text, 50)
```

One `xor + popcount` per doc in the corpus. Returns top-50 by fingerprint similarity. ~0.3 ms on a 20k-frame corpus.

### Layer 2 — BM25 scoring (mem0-parity)

Added 2026-04-22. Gated by query route (only runs on PureLexical + FullHybrid).

```
bm25_raw = engine.core.bm25_score_docs(query_text)  // HashMap<String, f32>
```

Uses the existing Porter2-stemmed inverted index + IDF table. Produces raw BM25 scores.

Then sigmoid-normalize (mem0's `normalize_bm25`):

```
(midpoint, steepness) = match n_terms {
    <=3  => (5.0, 0.7),
    <=6  => (7.0, 0.6),
    <=9  => (9.0, 0.5),
    _    => (12.0, 0.5),
};
bm25_norm[did] = 1.0 / (1.0 + exp(-steepness × (raw[did] - midpoint)))
```

Cap contribution at `max_sca × 0.6` so semantic still leads.

### Layer 3 — phrase / entity extraction

From the query:

- **Film/song/movie/book titles** — `"movie Inception"` → extract `"Inception"`
- **"of X" entity** — `"life of Einstein"` → extract `"Einstein"`
- **Multi-word proper nouns** — `"Caroline Smith met John"` → `["Caroline Smith", "John"]`

Each phrase is searched in the corpus with morphological expansion (strip `ers`/`ing`/`ed`/`es`/`s`). Docs matching the rarest query phrases get injected into the candidate pool with a floor score.

### Layer 4 — hyphen normalization (2026-04-22)

Corpus texts are hyphen-stripped at index time (`"de-stress"` → `"destress"`). Queries are tokenized on spaces; hyphenated query words are tried in both split and joined forms. This makes `"destress"` query find `"de-stress"` doc.

Applied in `normalize_for_match(s)` and the query-variant expander in `SaidFile::recall`.

### Layer 5 — entity-speaker boost (2026-04-22, single-word + additive 2026-06-22)

Extracts capitalized proper nouns from the query — **both** multi-word sequences
(`Caroline Smith`) **and** single capitalized words (`Mara`, `Melanie`). Single-word
extraction filters question words and sentence-initial caps using the canonical
`ASK_STOPWORDS` list (one source of truth — `what`/`who`/`which`/`the`/…), and skips
the first token (its capital is grammatical, not an entity).

Docs containing the entity get the boost **added on top of** their SCA semantic score
(`+20% of max_sca`), **not** an overwrite to a flat value. This is load-bearing: when
one entity has many memories (e.g. several facts about `Mara`), an overwrite tied them
all at the same score and erased the semantic ranking that distinguishes them; the
additive form keeps the semantic signal as the tie-break so the *right* `Mara` memory
wins. Entities not already in the SCA candidate pool are injected at a floor so they
can rank at all.

Particularly helpful for dialogue-heavy corpora (LoCoMo) where questions like "What did
Melanie say?" need to prefer Melanie's turns, and for personal-memory brains where many
notes share a subject.

### Layer 6 — graph fan-out (2026-04-22)

"Docs similar to the top hit." For each of the SCA top-3, re-query using a 120-char excerpt of the doc's body as the query text. Neighbors found by this secondary search get added to the candidate pool with per-doc accumulated scores (a doc similar to MULTIPLE seeds ranks higher than one similar to just one seed).

Cost: 3 extra `search_internal` calls × ~1 ms each. `.said`'s answer to mem0's graph layer — no triples, no LLM, just fingerprint neighborhood.

### Layer 7 — candidate merge + re-rank

```
candidates = SCA top-50 ∪ phrase-match injection ∪ entity-expansion pool ∪ graph neighbors
```

For each candidate:

```
base_score =
    if specific_docs contains did AND in sca_top_10:
        sca_score + grep_boost
    else:
        sca_score

final_score = base_score
            + bm25_norm[did] × max_sca × bm25_weight_mult
            + entity_boost (if query named entities, did contains them)
```

Sort by `final_score` desc, take top_k.

### Layer 8 — iterative multi-hop bridge (conditional)

Fires when `reranked[0].score - reranked[1].score < 1.5` (ambiguous top) AND the query contains relational words (`born`, `died`, `studied`, etc.). Extracts bridge entities from the top-3 docs, re-queries using `<bridge> <rel_context>`, folds results back in.

Historically the path that pushed WikimQA NDCG@10 to 1.0.

### Layer 9 — brain-state boost (applied in `SaidFile::recall`)

For every final hit:

```
recall_w = brain.get_recall_weight(did)          // 1.0 – 2.0
s_slow_boost = 1.0 + min(s_slow_read(q_emb) × 0.01, 0.5)
final = base_final × recall_w × s_slow_boost
```

Recently-hit docs rank higher; cross-doc-synthesizing docs get a bump from S_slow.

## `ask` fusion (3-engine, CLI + MCP)

Above the pure retrieval pipeline sits `sca_core::ask::ask` — the smart router that fuses three engines with confidence ranking:

| Engine | Confidence | Purpose |
|---|---|---|
| **Sym** (exact symbol name) | 1.00 | Code / entity lookup |
| **Grep** (literal keyword) | 0.40 – 0.95 | Shallow but precise |
| **SCA semantic** (full retrieval pipeline above) | 0.30 – 0.80 | Conceptual match |

Relative cutoff: drop results scoring below `top_score × 0.30` (`ASK_RELATIVE_CUTOFF`).
Minimum of 3 SCA results always pass (`ASK_SCA_GUARANTEED`).

Three correctness rules in the fusion (2026-06-22), all in shared code so CLI and MCP
behave identically:

- **SCA trust depth** (`ASK_SCA_TRUST_DEPTH = 10`). SCA semantic hits are kept up to
  the documented recall depth even with **zero** literal keyword overlap (the pure
  paraphrase case SCA exists for); only the deeper tail is gated on keyword presence.
  Previously the keyword gate started at rank 3, discarding correct paraphrase hits and
  collapsing recall@10.
- **Short digit discriminators are searchable.** Keyword extraction and the grep engine
  keep short tokens that contain a digit (`7`, `v2`, `B3`) — the high-IDF needle the
  docs guarantee retrieval for — instead of dropping every token under 3 chars. Keyword
  *presence* is matched on **whole tokens** (word boundaries), so `7` matches `office 7`
  but not `office 27`.
- **Result content-dedup.** Identical-content results (the same fact under several ids)
  collapse to one — keeping the highest-confidence copy — so duplicates don't fill the
  top-K or an LLM's context window. Storage and ids are untouched; every id is still
  retrievable by `get`.

Called by `said ask` CLI, MCP `ask` tool, and any direct Rust caller of
`sca_core::ask::ask(brain, query, top, deep, scope)`.

### Float rerank of the returned top-K (2026-06-22)

The 1-bit doc fingerprint keeps per-dim *direction* but drops *magnitude*, so among
near-collision candidates (e.g. one entity's many short memories — "Mara runs a bakery"
vs "Mara collects typewriters") the coarse score ties. Full 64-dim float cosine on the
*same* embedding separates them cleanly (the signal was never lost — it's the
sign-quantization that hides it). So after assembling the returned set, when the result
is **semantic-led** (no candidate has a discriminating multi-keyword lexical match),
`ask` re-encodes the query + each returned candidate's stored text and reorders by float
cosine — the QJL near-collision recovery from [14.1](../14-novel-mechanisms/14.1-qjl-asymmetric.md)
/ [14.8](../14-novel-mechanisms/14.8-matryoshka-signbit.md). Only the handful of returned
candidates are re-encoded (~80 µs each); **no storage change**. Symbol hits stay pinned
above the semantic rerank, and lexically-discriminated queries (a unique token like a
number) skip the rerank so exact matches keep their order. Measured: same-entity rank-1
2/5 → 5/5, recall@1 at N=200 0.195 → 0.855, lexical needle preserved 30/30, recall@10 1.0.

### Auto-dream is in core (2026-06-22)

`ask()` (and the pillar-scoped `recall_by_pillar` that MCP `search` uses) call
`SaidFile::maybe_dream()` at the end — the **single** trigger for the recall-path dream
cycle. CLI `cmd_ask` and the MCP `ask`/`search` handlers no longer trigger dream
manually; every surface (CLI, MCP, Rust API, orchestrator) evolves brain state
identically because the trigger lives in core, not in each caller.

## Performance (measured)

| Corpus | Query | Layer 1 (SCA) | Layer 2-8 | Total |
|---|---|---|---|---|
| LoCoMo conv-26 (419 turns) | "What did Alice decide?" | 0.3 ms | 3 ms | 3 ms |
| willie.said (19,149 frames) | "where did Caroline move from?" | 2 ms | 10 ms | 12 ms |
| WikimQA (300 docs, 7031 passages) | benchmark query | 1 ms | 5 ms | 6 ms |

MTEB MEAN NDCG@10 for all four LongEmbed tasks: **0.9655** (hand-traced; every retrieval test rebuilds the full pipeline and the numbers are stable across changes).
