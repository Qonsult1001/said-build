# 3.3 — Brain (S_slow, recall-weight, dream)

The **Brain** is the learning state that evolves as users query the `.said` file. It's the only subsystem that mutates on reads (everything else is ingest-only). Lives in [`crates/sca-core/src/brain.rs`](../../../crates/sca-core/src/brain.rs); persisted in the `BRAN` section.

Zero LLM. Pure deterministic math. Three independent components, all active by default.

## 1. S_slow tensor — cross-document synthesis

**Shape:** 64 × 64 float matrix (16 KB). Accumulates the outer product of every remembered doc's embedding.

**Formula:**
```
S_slow ← S_slow × decay + emb^T · emb
```

with `decay = 0.999` and `emb` = 64-dim L2-normalized vector.

**What it buys you.** After N docs ingest, `S_slow` encodes "which dimensions of meaning co-occur." At query time, `s_slow_read(query_emb) = ||query · S_slow||` gives a score indicating how strongly the query connects to the accumulated knowledge. Two docs that share no words but talk about related concepts (e.g. "Eleanor's photonic inverters" and "Aura Systems licensing") contribute to the same principal axes of S_slow; a query about one gets a small synthesis score for the other.

**Magnitude discovery.** `s_slow_magnitude() = ||S_slow||_F` (Frobenius norm) naturally encodes recency: freshly-ingested docs dominate the tensor; older docs fade at the decay rate. Lookup "when was the last burst of ingest" = "when did magnitude grow fastest."

**Cost:** `s_slow_write` is O(dim²) = 4096 FLOPs per ingest. `s_slow_read` is the same. Negligible on any CPU.

## 2. Recall-weight — warm docs rank higher

**Shape:** `HashMap<String, DocRecallState>` — per-doc state.

```rust
pub struct DocRecallState {
    pub recall_weight: f32,        // 1.0 .. 2.0
    pub last_recalled_at: u64,
    pub recall_count: u64,
    pub burst_count: u32,
    pub burst_window_start: u64,
}
```

**On every successful recall hit:**
```
state.recall_weight = (state.recall_weight + base_boost + burst_bonus).min(2.0);
```

where `base_boost = 0.05`, `burst_bonus` scales up to `0.15` when a doc has been hit many times in a short window.

**On every `consolidate()` call (fires from dream):**
```
for each tracked doc:
  state.recall_weight *= decay_rate  // 0.98 by default
  if state.recall_weight < 1.01: state.recall_weight = 1.0  // drop from tracking
```

**At query time:**
```
final_score = sca_score × brain.get_recall_weight(doc_id)
            × s_slow_boost
```

Recency bonus: docs recalled in the last hour get up to +20% on top of their recall_weight, fading to 0 over 24 hours.

**What it buys you.** The brain self-calibrates to usage. Docs the user / agent actually cares about drift up; cold docs fade. No training, no retraining, no retuning.

## 3. Dream cycle — corpus-mean drift

**Purpose.** The SCA fingerprint binarization centre (`corpus_mean`) is computed once at first-build. As the corpus grows and the nature of queries changes, the optimal centre drifts. The dream cycle detects this and adjusts.

**Formula:**
```
corpus_mean ← corpus_mean + alpha × (query_mean - corpus_mean)
corpus_std  ← corpus_std  + alpha × (target_std  - corpus_std)
```

with `alpha = cross_influence = 0.05`, `query_mean = sum(query_embeddings) / count` (accumulated since last dream), and `target_std` computed from per-dimension deviation.

**Trigger.** `brain.dream(min_queries)` fires when `query_emb_count >= min_queries`. The threshold is **dynamic** per corpus size:

```rust
// sca_core::ask::dynamic_dream_threshold(active_frames)
let scaled = (active_frames / 10).max(50).min(500);
```

- Small brain (< 500 frames) → fires every **50 queries** (fast adaptation)
- Medium brain (500 – 50k) → every `frames / 10` queries
- Large brain (> 50k) → every **500 queries** (stable)

Auto-fires from CLI `said ask`, MCP `ask`, and MCP `search` after every call. Zero user action needed.

**What it buys you.** Fingerprint quantization becomes optimized for the actual questions being asked. A legal brain used mostly for temporal queries drifts its centre toward temporal-word discrimination. A code brain drifts toward identifier-heavy axes.

**Caveat: v2 disabled the content-consolidation path.** An earlier "Dream v1" wrote Semantic frames from clustered Episodic frames. Measurement showed it hurt LoCoMo by ~2 points (clustering without semantics produces noisy summaries). Decision 5 v2 (2026-04-22) stubbed `SaidFile::run_dream_content` as a no-op. The brain-state dream (all three components above) remains active — that's the genuinely-valuable math. Content consolidation moves to the caller's LLM at read time (BYO-LLM).

## Public surface

```rust
pub struct Brain {
    pub s_slow: Vec<f32>,
    pub s_slow_dim: usize,       // 64
    pub s_slow_decay: f32,       // 0.999
    pub query_emb_count: u64,    // since last dream
    pub consolidation_cycles: u32,
    // ... per-doc state, etc.
}

impl Brain {
    // Writes
    pub fn s_slow_write(&mut self, embedding: &[f32]);
    pub fn log_query(&mut self, query: &str, doc_id: &str, score: f32);
    pub fn accumulate_query_embedding(&mut self, q_emb: &[f32]);

    // Reads
    pub fn s_slow_read(&self, q_emb: &[f32]) -> f32;
    pub fn s_slow_magnitude(&self) -> f32;
    pub fn get_recall_weight(&self, doc_id: &str) -> f32;

    // Lifecycle
    pub fn consolidate(&mut self) -> usize;
    pub fn dream(&mut self, mean: &[f32], std: &[f32], min_queries: u64)
        -> Option<(Vec<f32>, Vec<f32>)>;

    // Persistence
    pub fn serialize(&self) -> Vec<u8>;
    pub fn deserialize(bytes: &[u8]) -> Result<Brain, String>;
}
```
