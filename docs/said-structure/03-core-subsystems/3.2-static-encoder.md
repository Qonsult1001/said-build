# 3.2 — Static encoder (`said-lam-static-4M`)

The encoder that turns text into a **128-dim** float vector, which SCA then 1-bit-quantizes into a
fingerprint. Lives outside the SAID-ECHO repo in the sibling private repo
[`SAID-LAM-private`](../../../SAID-LAM-private/).

## The model

The SHIPPING encoder is **`said-lam-static-4M`** — a **Model2Vec** static embedding distilled from
`BAAI/bge-base-en-v1.5` via PCA reduction to **128 dimensions** (with Zipf weighting). It is the model
compiled into every bundle (`include_bytes!` in `crates/sca-core/src/latent_cluster.rs`). From
[`SAID-LAM-private/said-lam-static-4M/config.json`](../../../SAID-LAM-private/said-lam-static-4M/config.json):

```json
{
    "model_type": "model2vec",
    "architectures": ["StaticModel"],
    "tokenizer_name": "baai/bge-base-en-v1.5",
    "apply_pca": 128,
    "apply_zipf": true,
    "hidden_dim": 128,
    "seq_length": 1000000,
    "normalize": true
}
```

> **Encoder upgrade (2026):** the original `said-lam-static` was a 64-dim nomic distillation. The shipping
> model is now the **128-dim 4M bge-base distillation** — `apply_pca: 128`, so fingerprints and SCRM are
> 128-wide (see `brain.rs`: the recall matrix re-inits to dim×dim for the 4M encoder). Doubling the
> dimension raises the single-vector retrieval ceiling (arXiv:2508.21038: the ceiling scales with `d`),
> which is why recall numbers improved without any scorer change. Older 64-dim brains must be rebuilt
> (`said reindex`) to be comparable — fingerprints across dims are incomparable.

## File sizes (actual)

| File | Size | Purpose |
|---|---|---|
| `model.safetensors` | **15 MB** | PCA-reduced embedding matrix (vocab × 128 dims) |
| `tokenizer.json` | **668 KB** | WordPiece vocab (provenance: bge-base) |
| `config.json` | 1 KB | the config shown above |
| **Total** | **≈ 16 MB** | complete encoder |

Compared to the full `bge-base-en-v1.5` transformer (~440 MB), the static encoder is **~27× smaller**. The
PCA + Zipf weighting replace the full transformer forward pass — every token has a precomputed 128-dim
vector, and document encoding is mean-pooling over those tokens.

### Own tokenizer (no HuggingFace runtime dependency)

`config.json`'s `tokenizer_name: baai/bge-base-en-v1.5` is the model's **provenance** (what it was distilled
from), NOT a runtime call. `.said` ships its **own hand-written WordPiece tokenizer + pooling**
(`OwnStaticEncoder`, `crates/sca-core/src/latent_cluster.rs`) so the encoder is fully self-contained — no
HF `tokenizers` crate in the hot path, USB-stick portable. It is **bit-identity gated**: `OwnStaticEncoder`
must produce embeddings bit-for-bit identical (within f32 rounding) to the model2vec `StaticEncoder` across
a battery of english/SQL/C#/identifier/unicode/CJK/>512-token texts, locked by
`crates/sca-core/tests/test_own_tokenizer.rs` (if it goes RED, the own path diverged and must not ship).
WordPiece specifics: `max_input_chars_per_word = 100` (longer → `[UNK]`), char pre-truncation past the
token limit.

## Inference cost

On a single CPU core, no GPU:

| Operation | Time |
|---|---|
| Tokenize 100-word doc | ~50 μs |
| Look up 128-dim vectors for all tokens | ~10 μs |
| Mean-pool + L2 normalize | ~5 μs |
| **Total per doc** | **~65 μs** |
| **Batch of 100 docs** | **~4 ms** |

Compared to a transformer encoder that costs 5-30 ms per doc on CPU, this is **50-500× faster**. The quality loss is marginal (MTEB LongEmbed scores are state-of-art; see [3.1 SCA](3.1-sca-engine.md)) because PCA-reduced token embeddings retain most of the information content for the short-context tasks `.said` cares about.

## How `.said` finds the encoder

The CLI's `try_load_encoder` (used by **every** command, read and write) loads in this order:

1. **Embedded model first** — when built with `embed-model` (every shipping bundle), `auto_load_encoder()`
   loads the encoder compiled into the binary via `include_bytes!`. Zero external files.
2. **External file paths** — only if no embedded model is present, it falls back to `ENCODER_PATHS`:

```rust
const ENCODER_PATHS: &[&str] = &[
    "said-lam-static",
    "SAID-LAM-private/said-lam-static",
    "../SAID-LAM-private/said-lam-static",
    "../../SAID-LAM-private/said-lam-static",
    // ... plus the built binary's sibling folder
];
```

> **Embedded-first is load-bearing.** Earlier, `try_load_encoder` checked only `ENCODER_PATHS`. On a
> shipping bundle (no external folder on disk), read commands (`query`/`ask`/`recall`) opened a brain
> with **no encoder**, so `encode_query` returned `None` and SCA semantic search silently returned 0
> results — even though the model was baked in. The write path (`add`/`init`) already used the embedded
> loader, which masked the bug. Fixed by making `try_load_encoder` try the embedded model first. See
> the regression test `crates/sca-core/tests/test_embedded_encoder_semantic_recall.rs`.

For **non-embedded** builds (the bare `static-embed` library, no `embed-model`), the first external path
that exists + loads cleanly wins. Such users typically:

- Clone `SAID-LAM-private` next to `SAID-ECHO`, so the relative path works
- Or copy `said-lam-static/` next to the `said` binary for zero-config operation

## Feature flag — `static-embed`

The encoder is loaded only when the `static-embed` Cargo feature is enabled. Without it, `.said` still works for grep + symbol + lexical paths, but `recall()` returns empty (no fingerprints can be computed for queries).

Default Cargo features on SAID-ECHO include `static-embed`, so every normal build has the encoder wired up. The `embed-model` feature goes further — bundles the encoder's 4.8 MB into the binary via `include_bytes!`. That bloats the binary but means zero external files (USB-stick portable).

See [9 Cargo features](../09-cargo-features.md).

## Using it via the Rust API

```rust
let mut engine = ScaEngine::new();
engine.load_static_encoder("SAID-LAM-private/said-lam-static")?;

let query_emb: Vec<f32> = engine.encode_query("what does Alice like?")
    .expect("encoder must be loaded");
// query_emb is 128 floats, L2-normalized
```

## Why Model2Vec over full transformer

**Faster:** 50-500× speedup on CPU-only hosts.
**Smaller:** 4.8 MB vs ~550 MB.
**Stable:** no random initialization, no quantization drift between runs.
**Offline:** no HuggingFace download at first-run.
**BYO-LLM compatible:** no inference server needed; `.said` stays a single-file portable brain.

Trade-off: cannot handle very long passages well (no attention). Mitigation: `.said`'s passage engine chunks long docs at 512 words with 256-word stride, so the encoder only sees bite-sized contexts. See [`recall::PassageEngine`](../../../crates/sca-core/src/recall.rs).

## Swapping the encoder

In principle, any Model2Vec-shaped encoder with the same `hidden_dim` (128) would drop in. To change dim:

1. Update `SAID_MAGIC` and bump `SAID_VERSION` (fingerprints become incomparable)
2. Retrain or re-distil from a larger base
3. Rebuild existing `.said` files with `said reindex`

We swapped the 64-dim nomic model for the 128-dim 4M bge-base distillation in 2026 (raises the retrieval
ceiling; brains must be reindexed across the dim change). 128 dim is the current sweet spot for MTEB-class
tasks at this quantization tier.

## Citation

Based on Model2Vec (2024, Minishlab) which distils frozen transformer encoders via PCA + Zipf weighting.
Base model: `BAAI/bge-base-en-v1.5` (BAAI, 2024) — the 128-dim 4M distillation (`said-lam-static-4M`). The
runtime tokenizer is `.said`'s own WordPiece implementation, bit-identical to the model2vec path.
