# 3.4 — FrameStore (compression, blocks, dedup, lineage, tombstones)

The `FrameStore` owns every frame: stores them compressed, tracks lineage, enforces dedup, serves reads from a block cache, and honors legal holds. Lives in [`crates/sca-core/src/frames.rs`](../../../crates/sca-core/src/frames.rs).

## Responsibilities

1. **Store** — accept frame writes, compress them, put them on disk
2. **Retrieve** — decompress on demand, cache decompressed blocks in RAM
3. **Dedup** — BLAKE3 content-addressable: identical payloads share a slot
4. **Lineage** — re-writes of an existing `doc_id` tombstone the old frame (byte-exact-restorable)
5. **Tombstones** — mark-don't-delete; physically reclaim only when `drop_history` runs
6. **Legal-hold** — tag-based block on `drop_tombstones` / retention sweeps
7. **Serialize** — produce `FTOC` section bytes at save

## In-memory layout

```rust
pub struct FrameStore {
    frames: Vec<FrameMeta>,                    // the TOC (all frames ever)
    doc_id_map: HashMap<String, usize>,        // doc_id → index in frames[]  (Active only)
    next_id: u64,                              // monotonic frame id counter
    pending: Vec<PendingFrame>,                // writes not yet flushed to disk
    compression_level: i32,                    // 3 (fast) or 19 (max)
    zstd_dict: Option<Vec<u8>>,                // trained dictionary (H.265 GOP-style)
    blocks: Vec<CompressedBlock>,              // zstd-compressed block region
    block_map: HashMap<u64, (usize, usize)>,   // frame_id → (block_idx, intra_block_idx)
    block_cache: HashMap<usize, Vec<u8>>,      // block_idx → decompressed bytes (hot cache)
    encryption_key: Option<[u8; 32]>,          // AES-256-GCM key (optional)
}
```

Every mutation touches `pending`; `save()` / `compact()` is the only time `frames` and `blocks` grow.

## Write path (simplified)

```rust
pub fn put_with(&mut self, opts: &PutOptions) -> u64 {
    self.put_internal(opts.doc_id, opts.content.as_bytes(), opts.title,
        opts.memory_type, opts.memory_kind, opts.subject, opts.scope, opts.tags.clone())
}

fn put_internal(&mut self, doc_id: &str, content: &[u8], ...) -> u64 {
    let frame_id = self.next_id;
    self.next_id += 1;

    // 1. lineage: if an Active frame exists for doc_id, tombstone it
    if let Some(&old_idx) = self.doc_id_map.get(doc_id) {
        if self.frames[old_idx].status == FrameStatus::Active {
            self.frames[old_idx].status = FrameStatus::Tombstone;
            self.frames[old_idx].superseded_by = Some(frame_id);
        }
    }

    // 2. build FrameMeta (offset=0 until flush), push to pending
    let meta = FrameMeta { id: frame_id, doc_id: doc_id.into(), status: Active, ... };
    self.pending.push(PendingFrame { meta, compressed_data: vec![] });  // empty until compress

    frame_id
}
```

Actual compression happens later in `flush_pending(start_offset)` or `flush_block_pending_with_source(...)`:

```rust
for each pending frame:
    payload = compress(frame.content)  // Plain | Zstd | ZstdDict | ZstdDictBlock
    checksum = blake3::hash(&payload)
    frame.offset = current_write_offset
    frame.compressed_len = payload.len()
    frame.uncompressed_len = frame.content.len()
    frame.checksum = checksum
    frame.encoding = chosen_encoding
    append payload bytes to output buffer
```

## Compression routing

For each pending batch, the store picks an encoding:

- **First save (no dict yet):** `Plain` — just raw bytes. Fast write; poor ratio.
- **After `compact()` trained a dict:** `ZstdDictBlock` — multiple frames share a zstd block. Best ratio.
- **Single-frame writes between compacts:** `ZstdDict` — standalone zstd with the trained dict. Moderate ratio, random-access friendly.
- **Encryption feature enabled:** wraps the zstd output in AES-256-GCM (`Aes256Gcm` encoding).

See [2.4 Block compression](../02-file-format/2.4-block-compression.md) for block-level detail.

## Dedup — `latent_cluster`

When multiple frames have identical content (exact BLAKE3 match), they share a single payload slot. The secondary frame gets a `FrameMeta` pointing at the primary's `offset + compressed_len + checksum`. Saves bytes on highly-repeated ingests (e.g. SQL schemas with 100 similar tables).

Implemented in [`sca_core::latent_cluster`](../../../crates/sca-core/src/latent_cluster.rs).

## Read path

```rust
pub fn get(&self, frame_id: u64, file_bytes: &[u8]) -> Option<Vec<u8>> {
    let frame = self.frames.iter().find(|f| f.id == frame_id)?;
    match frame.encoding {
        Plain => Some(file_bytes[frame.offset..frame.offset + frame.compressed_len].to_vec()),
        Zstd => zstd::decompress(&file_bytes[...]).ok(),
        ZstdDict => zstd::decompress_using_dict(&file_bytes[...], &self.zstd_dict).ok(),
        ZstdDictBlock => {
            let (block_idx, intra_idx) = self.block_map[&frame_id];
            // Cache: decompress the block once, slice into it repeatedly
            let block = self.block_cache.entry(block_idx).or_insert_with(|| {
                zstd::decompress_using_dict(&self.blocks[block_idx].bytes, &self.zstd_dict)
            });
            Some(block[intra_idx.start..intra_idx.end].to_vec())
        }
        Aes256Gcm => aes_gcm::decrypt(&file_bytes[...], &self.encryption_key?).ok(),
    }
}
```

**Hot path:** first access = decompress block (~500 μs). Repeat access = 7 μs (cache slice + copy).

## Lineage + tombstones

Every `put_with` on an existing `doc_id` promotes the old head to `Tombstone`, sets `superseded_by = new_id`. Walking the `superseded_by` chain backward reconstructs every version.

`admin_tombstone_records()` returns all non-Active frames, newest-first — the "Recycle Bin" view.

`admin_restore_tombstoned(doc_id)` finds the newest tombstone for that doc_id, flips it to `Active`, and demotes the current Active head to `Tombstone` so the one-Active-per-doc_id invariant holds.

See [Row 42 Admin CLI](../05-features/row-42-admin.md) for the user-facing surface.

## Physical deletion

Two-step:

1. **Mark Deleted** — `drop_tombstones()` / `drop_tombstones_keep(N)` / `mark_frame_deleted(frame_id)`. Flips `Tombstone → Deleted` (or `Active → Deleted` for explicit `forget()`). Frames under `legal_hold:*` tag are **skipped**.
2. **Reclaim bytes** — `compact()` with the delete-reclaim pass. Rewrites blocks, excluding Deleted frames. This is the irreversible step.

The gap between mark and reclaim gives admins a recovery window: a frame marked Deleted but before compact is still byte-restorable by flipping the status back.

## Legal hold

From [`frames.rs`](../../../crates/sca-core/src/frames.rs):

```rust
fn is_under_legal_hold(tags: &[String]) -> bool {
    tags.iter().any(|t| t.starts_with("legal_hold:") || t.as_str() == "legal_hold")
}
```

Any frame with `legal_hold:<case_id>` tag is immune to `drop_tombstones` and `drop_tombstones_keep`. Multiple concurrent holds (e.g. `legal_hold:CASE-A` and `legal_hold:CASE-B`) each block deletion independently — releasing one doesn't remove the other.

`mark_frame_deleted()` also refuses held frames as a double-check, so a caller-level bug can't accidentally reap a held frame.

## Pillar persistence — `set_pillar`

Added 2026-04-22 to fix the Factual→Semantic collapse (see [Known limitations](../11-known-limitations.md)).

```rust
pub fn set_pillar(&mut self, frame_id: u64, pillar: Pillar) -> bool;
pub fn put_with_pillar(&mut self, opts: &PutOptions, pillar: Pillar) -> u64;
```

`put_with_pillar` is `put_with` + explicit pillar write in one call. Preferred over bare `put_with` when the caller cares about `FrameMeta.pillar` (i.e. always for the `remember_as_*` family).

## Serialization — `FTOC` section

`serialize_toc()` emits every FrameMeta in sequence. Layout per entry:

- `u64 id`
- `u32 doc_id_len` + `doc_id` bytes
- `u64 offset`
- `u32 compressed_len`, `u32 uncompressed_len`
- `[u8; 32]` checksum
- `u8` encoding
- `u8` status
- `u16 title_len + title` bytes (0 = no title)
- `u64 created_at`
- `u8` memory_type, memory_kind, subject, scope
- `u32 tags_count` + per tag: `u16 len + bytes`
- `u8 has_superseded` + `u64 superseded_by` (if set)
- `f32 semantic_delta`
- `u8 pillar`

Old readers (pre-pillar) stop before the `pillar` byte and use `Pillar::from_memory_type(memory_type)` as a fallback. v7_1 writers always emit the byte.
