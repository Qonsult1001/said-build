# 3.1 — SCA engine

**Said Crystalline Attention** (SCA) is the semantic search core: 1-bit fingerprints, Hamming-distance ranking, optional 16-view holographic encoding. Lives in [`crates/sca-core/src/crystalline.rs`](../../../crates/sca-core/src/crystalline.rs) with the higher-level wrapper in [`crates/sca-core/src/engine.rs`](../../../crates/sca-core/src/engine.rs).

## What it is

SCA encodes every doc into a fixed-width **binary fingerprint** (64 bits by default). Query encoding is the same. Semantic similarity becomes Hamming distance over bit vectors — one `xor + popcount` instruction per comparison.

Why binary:
- 1-bit precision is **enough** for coarse semantic structure on short passages (WikimQA paper result, replicated in Rust)
- Hamming distance is **two orders of magnitude faster** than cosine over floats (CPU: AVX2 popcount; GPU: optional wgpu compute shader)
- Binary fingerprints are **500× smaller** than 768-dim float embeddings. A 20k-frame brain stores ~160 KB of fingerprints vs ~60 MB of embeddings.

Proven scores on MTEB LongEmbed:

| Task | NDCG@10 | Target |
|---|---|---|
| `LEMBNeedleRetrieval` | **1.00000** | 1.00000 |
| `LEMBWikimQARetrieval` | **1.00000** | 0.93983 (+6.40%) |
| `LEMBSummScreenFDRetrieval` | **0.97974** | 0.96586 (+1.44%) |
| `LEMBQMSumRetrieval` | **0.89220** | 0.85756 (+4.04%) |

## Encoding pipeline

From text to 1-bit fingerprint:

```
text ────► static encoder ────► 64-dim float vector ────► IDF-weighted sum
                                           │
                                           ▼
                                     corpus-mean centre
                                           │
                                           ▼
                                      sign-quantize
                                           │
                                           ▼
                                    8-byte fingerprint (64 bits)
```

Concretely (`CrystallineCore::add_docs_quantized`):
1. For each doc, tokenize + encode with `said-lam-static` → `Vec<f32>` of length 64
2. Centre: `vec - corpus_mean` (corpus mean is computed on first build, then persisted in SCRM)
3. Quantize: `bit_i = 1 if vec[i] >= 0 else 0`
4. Pack bits into 8 bytes

At search time the query goes through the same pipeline. Distance is `popcount(query_bits XOR doc_bits)`; semantic similarity = `1.0 - distance / 64.0`.

## Quantization tier — `matrix_quantized`

The hot storage is `CrystallineCore.matrix_quantized: Vec<u8>` — contiguous bytes laid out so Hamming scans SIMD nicely.

Layout: `bytes_per_passage * num_passages`, where each passage is one contiguous 8-byte (or 128-byte holographic) fingerprint.

- Standard mode: 8 bytes × N_passages = **8 KB per 1000 passages**
- Holographic 16-view: 128 bytes × N_passages = **128 KB per 1000 passages**

## Holographic 16-view (optional)

When enabled (`engine.core.set_holographic_16view(true, Some(scale))`), each doc gets **16 independent fingerprints** — one per rotated projection of the embedding space. Search uses the **maximum** similarity across views, giving robustness to small semantic shifts.

Cost: 16× storage and 16× Hamming compute. Benefit: higher recall on semantically-close-but-keyword-different queries.

Currently **off by default**. MTEB and LoCoMo runs use `set_holographic_16view(false, None)`. Turning it on is a 1-line caller change.

## Query routing — `analyze_query`

Every query is classified into one of three routes:

| Route | When | Alpha (semantic vs lexical blend) |
|---|---|---|
| `PureLexical` | code intent words present ("fn", "class", "SELECT") OR numeric passkey pattern | 0.85 (heavy lexical) |
| `PureSemantic` | short discourse, low IDF, no high-IDF term, no OOV | 0.00 (pure semantic) |
| `FullHybrid` | everything else — the default for intent queries | 0.70 |

The router is in `CrystallineCore::detect_query_type(query) -> &'static str`. It's called from `recall_fused` to gate whether BM25 should fire (skipped on `PureSemantic` to preserve paraphrase behaviour).

## How it plugs into SaidFile

```
SaidFile
  ├─ engine: ScaEngine
  │    ├─ core: CrystallineCore    ← SCA proper
  │    ├─ brain: Brain              ← recall-weight, S_slow, dream
  │    └─ static_encoder: Option    ← said-lam-static
  └─ frames: FrameStore              ← content bytes + metadata
```

`SaidFile::recall(query, top_k)` orchestrates all of them — see [3.5 retrieval pipeline](3.5-retrieval-pipeline.md).

## Trade-offs

**Pros:**
- 0.3 ms per query on 20k-frame corpus
- 500× smaller storage than float embeddings
- GPU-optional (wgpu compute shader with `gpu` feature)
- Zero neural inference at search time — just Hamming distance

**Cons:**
- 1-bit precision loses fine-grained semantics on very-similar phrases. Paraphrase with no word overlap can miss (addressed partly by router's `PureSemantic` route, partly by `s_slow` cross-doc synthesis).
- Corpus mean must be representative; on very small brains (<50 docs) the centre is noisy. We recompute on growth.
- No native negation handling (SCA scores "not a dog" similar to "a dog"); the retrieval pipeline's BM25 + query variants pick up the difference at the lexical layer.
