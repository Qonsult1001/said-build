# 2.3 — Frame layout

A **frame** is the atomic unit of stored content. Every `remember`, `ingest`, or admin operation manipulates one or more frames. This page explains what a frame is in memory (`FrameMeta`) and what a frame is on disk (compressed payload with BLAKE3 checksum).

## In-memory — `FrameMeta`

From [`crates/sca-core/src/frames.rs`](../../../crates/sca-core/src/frames.rs):

```rust
pub struct FrameMeta {
    pub id: u64,                  // monotonic, never reused
    pub doc_id: String,           // user-provided or auto-generated
    pub offset: u64,              // byte offset in the file where payload starts
    pub compressed_len: u32,      // zstd-compressed size
    pub uncompressed_len: u32,    // original size
    pub checksum: [u8; 32],       // BLAKE3 of the COMPRESSED payload
    pub encoding: FrameEncoding,  // Plain | Zstd | ZstdDict | ZstdDictBlock | Aes256Gcm
    pub status: FrameStatus,      // Active | Tombstone | Deleted
    pub title: Option<String>,
    pub created_at: u64,          // unix seconds
    pub memory_type: MemoryType,  // Episodic | Factual | Procedural | Relational | Meta
    pub memory_kind: MemoryKind,  // Event | Fact | Preference | Rule
    pub subject: MemorySubject,   // User | Agent | System | World
    pub scope: MemoryScope,       // Personal | Shared | Public
    pub tags: Vec<String>,        // freeform — `pillar:semantic`, `user_id:42`, etc.
    pub superseded_by: Option<u64>,  // lineage link (points to replacement frame_id)
    pub semantic_delta: f32,         // 0..=1 fingerprint-Hamming distance to predecessor
    pub pillar: Pillar,              // Episodic | Semantic | Procedural | External | Code | Memory
}
```

## Status lifecycle

```
     put_with() / remember_with_pillar()
           │
           ▼
     ┌──────────┐
     │  Active  │ ◄──────────────────────── admin_restore_tombstoned()
     └──────────┘
           │
           │ put_with same doc_id  (lineage replacement)
           │ OR admin_restore demotes the current head
           ▼
     ┌──────────┐
     │Tombstone │ ◄───── (still visible to lineage queries; drop_history moves to Deleted)
     └──────────┘
           │
           │ drop_tombstones() / drop_tombstones_keep() / retention-sweep
           │ (skipped on legal_hold:*)
           ▼
     ┌──────────┐
     │ Deleted  │ ◄───── (scheduled for physical removal on next compact)
     └──────────┘
           │
           │ compact() with the `drop_deleted` pass
           ▼
      (physically removed from the file — bytes reclaimed)
```

**Tombstone is byte-exact-restorable.** The compressed payload remains on disk; `said checkout --version N` writes a new Active frame with the same bytes.

**Deleted is scheduled for physical removal.** Once compact runs, the payload bytes are gone — unrecoverable without a file-system-level restore.

## On-disk — compressed payload

Each frame's payload sits in one of several encodings:

| FrameEncoding | Layout | When used |
|---|---|---|
| `Plain` | raw bytes | fresh frames before the first `compact()` — fast writes, no compression |
| `Zstd` | `zstd::compress(content)` | standalone compressed frame |
| `ZstdDict` | `zstd::compress_with_dict(content, trained_dict)` | after `compact()` built a shared dict |
| `ZstdDictBlock` | part of a compressed BLOCK (multiple frames share one zstd stream) | after compact with block-256 — default post-compact |
| `Aes256Gcm` | encrypted envelope (with `encryption` feature) | per-frame encryption — admin-controlled key |

Compression level defaults to `3` (fast); `19` available for max-ratio on cold data.

## BLAKE3 checksum

Every frame carries a BLAKE3 hash of the **compressed** payload (not the plaintext). On-disk integrity is verified on read:

```rust
let actual = blake3::hash(&disk_bytes);
if actual != frame.checksum { return Err("corrupt"); }
```

Benefits:
- Detects bit flips / disk corruption before decompression (cheaper than decompressing and finding the error there).
- Enables content-addressable dedup via `latent_cluster`: two frames with the same BLAKE3 share a single payload slot.

## Lineage chain

When a frame with the same `doc_id` is re-written, the old frame is NOT deleted — it's marked `Tombstone` and its `superseded_by` field gets set to the new frame's `id`. Walking `superseded_by` from the current Active head backward reconstructs every version ever stored.

```
doc_id "memo.md" over time:

  frame #0  Active       ┐
     │                   │
     │ re-remember       │ First version.
     ▼                   ┘
  frame #0  Tombstone    ┐ superseded_by=#1
  frame #1  Active       │ Second version.
     │                   │
     │ re-remember       │
     ▼                   ┘
  frame #0  Tombstone    superseded_by=#1
  frame #1  Tombstone    superseded_by=#2
  frame #2  Active       ← current head
```

Every version is byte-exact-restorable via `said checkout --version N` (N=0 is genesis, N=2 is current HEAD in this example).

## Semantic delta

`FrameMeta.semantic_delta` records the 1-bit XOR+POPCNT Hamming distance between consecutive versions of the same doc_id, normalized to `[0, 1]`:

- `0.00` — fingerprint-identical (whitespace-only change); `put()` can skip
- `0.10` — small change (typo fix, one-line edit)
- `0.50` — major rewrite (half the dimensions flipped)
- `1.00` — totally different content

Genesis frames (first time a doc_id appears) use `0.0`. The delta is computed at `put()` time from the current Active frame's stored fingerprint; no re-encoding needed.

## Auto-generated doc_ids

When the caller passes `doc_id: None` to `remember_with_pillar`, the writer auto-generates one with a pillar-indicative prefix:

- `ep_<n>` — Episodic
- `sem_<n>` — Semantic
- `proc_<n>` — Procedural
- `ext_<n>` — External
- `code_<n>` — Code
- `mem_<n>` — Memory (default / legacy)

`<n>` is `FrameStore::total_count()` at write time. Stable within a session; not a hash, not globally unique across brains.

## How a frame gets on disk (write path)

```
remember_with_pillar(content, Pillar::Semantic)
  │
  ▼
put_with(opts) ────────► put_internal(doc_id, bytes, ...)
                             │
                             ▼
                         build FrameMeta { id, offset=pending, compressed_len=0, ... }
                             │
                             ▼
                         push to self.pending (in-memory queue)
                             │
                             ▼
                         return frame_id  ← caller sees the id
```

The frame stays in `pending` until `save()` / `compact()` flushes it to disk:

```
save()
  │
  ▼
for each pending frame:
  compress_payload (Plain → Zstd → ZstdDict → ZstdDictBlock depending on batch context)
  compute BLAKE3 over compressed bytes
  append to file at offset
  update FrameMeta.offset + compressed_len + uncompressed_len + checksum + encoding
```

## How a frame gets read (read path)

```
read(doc_id)
  │
  ▼
doc_id_map[doc_id] → frame_index
  │
  ▼
frame = self.frames[frame_index]
  │
  ▼
match frame.encoding {
  Plain          => bytes,
  Zstd           => zstd::decompress(bytes),
  ZstdDict       => zstd::decompress_with_dict(bytes, self.zstd_dict),
  ZstdDictBlock  => {
    let (block_idx, intra_idx) = self.block_map[frame.id];
    let block = self.block_cache.entry(block_idx).or_insert_with(|| decompress_block(block_idx));
    block[intra_idx.start..intra_idx.end]
  },
  Aes256Gcm      => aes_gcm::decrypt(bytes, self.encryption_key),
}
```

Block cache keeps recently-decompressed blocks in memory (~400 KB per block, 28 blocks on WikiMQA = ~11 MB). Repeat lookups hit the cache in ~7 μs.
