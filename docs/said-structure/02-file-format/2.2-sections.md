# 2.2 — All sections

Every section in a `.said` file starts with a 4-byte ASCII magic so readers can sanity-check the offset they found. Most sections live at a header-recorded offset; two (`MODE`, `AUDT`) are found by magic scan because they were added after the header layout was frozen.

## Section matrix

| Magic | Section | Required | Location found by | Shipped in |
|---|---|---|---|---|
| `SAID` | Header (72 bytes) | yes | offset 0 | v7 |
| (payload) | Compressed block region | yes | scrm_offset marks end | v7 |
| `DICT` | Trained zstd dictionary | no | `dict_offset` header field | v7 |
| `BLKT` | Block table | no | `blkt_offset` header field | v7 |
| `SCRM` | SCA fingerprints | **yes** | `scrm_offset` header field | v7 |
| `BRAN` | Brain state | yes | directly after SCRM | v7 |
| `MODE` | Deployment mode | no | magic scan | v7 (2026-04-22, post-release) |
| `AUDT` | Audit log | no | magic scan | v7 (2026-04-22, post-release) |
| `TRGM` | Trigram inverted index | no | `trgm_offset` header field | v7_1 |
| `SYMS` | Symbol table | no | `syms_offset` header field | v7_1 |
| `REFS` | Cross-file reference edges | no | `refs_offset` header field | v7_1 reserved |
| `CTXT` | Cached corpus texts (lowercased) | no | magic scan | v7_1 (temporarily disabled) |
| `FTOC` | Frame table of contents | **yes** | `toc_offset` header field | v7 |

Absence of an optional section is signalled by `offset == 0` (header-indexed) or magic not found (scan-based).

## Core sections

### SCRM — SCA fingerprints

**Magic:** `SCRM`
**Purpose:** 1-bit fingerprints for every indexed doc. The core of the semantic search path.
**Contents:** serialized `CrystallineCore` state — quantized matrix (`matrix_quantized: Vec<u8>`), doc ids, passage offsets, gammas, holographic-16-view flag. Roughly 8 bytes per doc (one 64-bit fingerprint) at default dim.
**Read at open:** yes, fully — but slim format loads breadcrumbs only; full format includes texts.
**Writer:** `ScaCore::serialize_breadcrumbs()` for slim, `state::serialize_state()` for full.

### BRAN — brain state

**Magic:** `BRAN`
**Purpose:** learned state that evolves with usage — `S_slow` tensor (64×64 semantic co-occurrence matrix, 16 KB), per-doc `recall_weight`, query log, dream cycle counter.
**Contents:** serialized `Brain` struct. See [Core 3.3 brain](../03-core-subsystems/3.3-brain.md).
**Read at open:** yes, bounded to a computed end (the section does NOT have a length prefix; reader stops at the start of TRGM / SYMS / REFS / TOC magic).
**Writer:** `Brain::serialize()`.

### FTOC — frame table of contents

**Magic:** `FTOC`
**Purpose:** per-frame metadata. The `FrameMeta` list; the authoritative record of every frame in the file (Active, Tombstone, Deleted).
**Contents:** length-prefixed list of serialized `FrameMeta` records — id, doc_id, offset, compressed_len, uncompressed_len, BLAKE3 checksum, encoding, status, title, created_at, memory taxonomy (type/kind/subject/scope), tags, superseded_by, semantic_delta, pillar (1 byte).
**Read at open:** yes, fully.
**Writer:** `FrameStore::serialize_toc()`.

## Optional sections

### DICT — trained zstd dictionary

**Magic:** `DICT`
**Purpose:** H.265-inspired shared compression context. Trained from corpus samples; significantly improves per-frame compression by eliminating cold-start overhead for domain vocabulary.
**Contents:** `DICT` magic (4) | `u32 dict_len` | raw zstd dictionary bytes.
**Read at open:** yes (cheap, the dict is small — typically 20-200 KB).
**Writer:** `FrameStore::get_dictionary()`.

### BLKT — block table

**Magic:** `BLKT`
**Purpose:** index for the compressed-block region. For Zstd-dict-block-encoded frames, the frame's offset points to the block's start; this table maps `frame_id → (block_index, intra_block_frame_index)` so readers can seek directly to the right frame without decompressing the whole block.
**Contents:** opaque serialized block-table bytes.
**Read at open:** yes.
**Writer:** built during compact + flush; serialized alongside block data.

### MODE — deployment mode

**Magic:** `MODE`
**Purpose:** brain-level immutable mode flag. `Portable` (embed full content) vs `Enterprise` (pointer-only).
**Size:** exactly 8 bytes — `MODE` magic (4) | mode byte (1, `0 = Portable`, `1 = Enterprise`) | 3 reserved zero bytes.
**Found by:** magic scan (post-header-freeze addition).
**Absent section:** treated as Portable — preserves back-compat for every file written before 2026-04-22.
**Writer:** `buf.extend_from_slice(MODE_MAGIC); buf.push(self.mode as u8); buf.extend_from_slice(&[0;3]);`

See [Row 37](../05-features/row-37-brain-mode.md).

### AUDT — audit log

**Magic:** `AUDT`
**Purpose:** append-only BLAKE3-chained log of mutating actions.
**Layout:** `AUDT` magic (4) | `u32 n_entries` | per entry: `u64 seq`, `u64 timestamp`, `u16 actor_len + actor bytes`, `u16 kind_len + kind bytes`, `u16 target_len + target bytes`, `u32 detail_len + detail bytes`, `[u8; 32] hash`.
**Chain:** each entry's `hash = BLAKE3(prev_hash || seq || ts || actor || 0x00 || kind || 0x00 || target || 0x00 || detail)`. First entry uses `prev_hash = [0; 32]`.
**Integrity:** `AuditLog::verify()` walks the chain and reports the first break point. Any tampering (byte-change in any past entry) fails verification.
**Found by:** magic scan.
**Writer:** `AuditLog::serialize()`, deserializer `AuditLog::deserialize(bytes)`.

See [Row 45](../05-features/row-45-audit.md) and [Core 3.7 audit](../03-core-subsystems/3.7-audit-log.md).

### TRGM — trigram inverted index

**Magic:** `TRGM`
**Purpose:** substring search (grep) accelerator. Without it, grep falls back to a linear scan across cached corpus texts (still fast but O(n) vs O(1)).
**Layout:** `TRGM` (4) | `u32 n_doc_ids` | per doc_id: `u16 len, utf8 bytes` | `u32 uncompressed_len` | `u32 compressed_len` | zstd-compressed raw trigram index bytes.
**Reader:** decompresses the raw bytes, then `TrigramIndex::deserialize_raw(raw)` rebuilds the posting-list tree.
**Writer:** `TrigramIndex::serialize_raw()` wrapped in a zstd compression pass (level 15).

### SYMS — symbol table

**Magic:** `SYMS`
**Purpose:** exact symbol-name lookup from AST chunking. Populates `said sym <name>`.
**Layout:** `SYMS` (4) | `u32 uncompressed_len` | `u32 compressed_len` | zstd-compressed raw symbol-table bytes. Uses the same `trigram_doc_ids` list as TRGM for doc_index translation — no duplicate doc_id table.
**Reader:** `SymbolIndex::deserialize_raw(raw)`.
**Writer:** `SymbolIndex::serialize_raw()` + zstd(15).

### REFS — reference edges

**Magic:** `REFS`
**Purpose:** cross-file reference edges (LSP-derived "goes to definition" / "find all references" cache). Frozen at init time so query paths don't need to re-parse.
**Status:** reserved offset; not yet implemented. Readers ignore it.

### CTXT — cached corpus texts (temporarily disabled)

**Magic:** `CTXT`
**Purpose:** per-doc lowercase text cache for grep rerank without decompression.
**Status:** currently disabled at the write site (flagged `if false` in `save()` while a block-corruption bug is investigated). Readers still honor the section if present on a file written by an older build.
**Layout:** `CTXT` (4) | `u32 compressed_len` | `u32 uncompressed_len` | zstd-compressed raw corpus dump.

## Section ordering on disk

```
[0..72]      header
[72..X]      compressed block region (frame payloads; X = scrm_offset)
[X..]        DICT (if present)
...          BLKT (if present)
...          SCRM
...          BRAN
...          MODE
...          AUDT
...          TRGM (if present)
...          SYMS (if present)
...          REFS (reserved)
...          FTOC (last; toc_offset points here)
```

Positions of MODE / AUDT / TRGM / SYMS / REFS are flexible — they're either at the header-recorded offset (when present) or scan-found (MODE, AUDT). Readers don't care which writer put them where; they honor whatever they find.
