# 2.1 — v7_1 header (byte-by-byte)

The header is the first 72 bytes of every `.said` file. It's the constant-time entry point: opening a file is a handful of u64 reads from this region, never a scan.

## Layout

```
offset  size  field               notes
──────  ────  ──────────────────  ─────────────────────────────────────────
[0..4]   4    magic "SAID"        always b"SAID" (ASCII)
[4..6]   2    version u16         always 7 today
[6..8]   2    flags u16           bit 0 = FLAG_EXTENDED_HEADER (v7_1)
[8..12]  4    frame_count u32     active frame count at save time
[12..20] 8    scrm_offset u64     SCRM section start; 0 never
[20..28] 8    toc_offset u64      FTOC section start; 0 never
[28..36] 8    dict_offset u64     DICT section start; 0 = no trained dict
[36..44] 8    blkt_offset u64     BLKT section start; 0 = no compressed blocks
[44..52] 8    trgm_offset u64     TRGM section start; 0 = no trigram index
[52..60] 8    syms_offset u64     SYMS section start; 0 = no symbol table
[60..68] 8    refs_offset u64     REFS section start; 0 = reserved/empty
[68..72] 4    reserved            zero
──────  ────
total   72 bytes
```

## Legacy v7 header (48 bytes)

Files written before v7_1 shipped use a 48-byte header (only offsets through BLKT). They're still loadable — the flag bit 0 is clear, so readers skip TRGM / SYMS / REFS scans. All functionality degrades gracefully:
- No trigram → grep falls back to linear scan on cached corpus text
- No symbol table → `said sym` returns empty
- No REFS → cross-file reference queries are not available

## Field semantics

### magic
Always `b"SAID"`. First sanity check on open.

### version (u16 little-endian)
Currently `7`. Incremented when on-disk structure changes in a way that old readers can't handle. New readers can read old files up to `version` (backward-compatible); old readers CAN'T read newer files (forward-incompatible by design).

### flags (u16 little-endian)
Bit 0 (`FLAG_EXTENDED_HEADER = 0x0001`) — signals v7_1 extended header (72 bytes vs legacy 48). Readers check this before reading offsets `[44..68]`.

Higher bits reserved for future use — add a new flag bit when a future section needs a header slot.

### frame_count (u32 little-endian)
Number of Active frames at save time. A hint, not authoritative — the FTOC section is the source of truth. Useful for pre-allocating vectors before TOC parse.

### section offsets (u64 little-endian)
Absolute byte offsets into the file. `0` means "section absent" for optional sections (DICT, BLKT, TRGM, SYMS, REFS). SCRM and FTOC must be present; their offsets cannot be zero in a valid file.

## Open-time procedure

From [`SaidFile::open`](../../../crates/sca-core/src/said_file.rs):

```
1. mmap the file
2. if len < 48: reject
3. check magic == "SAID"
4. read version; reject if > 7
5. read flags; if bit 0 set and len >= 72, read offsets [44..68]; else those = 0
6. read frame_count, scrm_offset, toc_offset, dict_offset, blkt_offset
7. for each non-zero offset, verify section magic at that offset; reject on mismatch
8. load DICT, then SCRM, then BRAN (right after SCRM), then optional sections
9. scan for MODE and AUDT magics (these post-date the header freeze)
10. load FTOC last — it anchors frame metadata
```

Total time for typical files: < 30 ms (mostly reading small sections; frame content stays un-decompressed until touched).

## Writing rule

Every save rewrites the whole file via atomic `.tmp` + rename. The save order is:
1. Compressed blocks (frame payloads)
2. DICT (if trained dictionary exists)
3. BLKT (block table)
4. SCRM (SCA fingerprints)
5. BRAN (brain state)
6. MODE (8 bytes)
7. AUDT (audit log)
8. TRGM (trigram index, if built)
9. SYMS (symbol table, if present)
10. REFS (reserved)
11. FTOC (frame TOC)

Header is then written at offset 0 with the resolved offsets. The WAL-safe write path (`state::write_safe`) writes to `.tmp` first, fsyncs, and renames — so partial crashes leave the original file untouched.
