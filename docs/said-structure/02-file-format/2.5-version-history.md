# 2.5 — Version history + migration rules

## Current version: `v7_1`

The file format is currently **v7_1** (72-byte header, flag bit 0 set). All new writes use this shape.

## Version matrix

| Version | Header size | Magic | New sections | Shipped |
|---|---|---|---|---|
| v1 - v6 | — | `SAID` | — | historical; no v7 readers support them |
| v7 | 48 bytes | `SAID` + version=7 + flag=0 | FTOC + SCRM + BRAN + optional DICT + BLKT | 2025 |
| v7_1 | 72 bytes | `SAID` + version=7 + flag=0x0001 | + TRGM + SYMS + REFS offsets | 2026-03 |
| v7_1 (post-release) | 72 bytes | same | + MODE (8 bytes, magic-scanned) | 2026-04-22 |
| v7_1 (post-release) | 72 bytes | same | + AUDT (variable-length, magic-scanned) | 2026-04-22 |

**No v8 yet.** The additions since v7_1 have been magic-scanned sections (MODE, AUDT) that don't require header layout changes — v7 readers see a valid v7_1 file and load what they know, ignoring the new sections. This is the cheapest path for frequent feature additions.

## Compatibility rules

### Forward-compatible sections (v7_1 additions)

A v7 reader can open a file that has TRGM / SYMS / REFS / MODE / AUDT — the header's `FLAG_EXTENDED_HEADER` bit is set but the reader ignores the extended offsets. Consequences:

- Grep / substring queries fall back from trigram lookup to linear scan — still correct, slightly slower on large corpora.
- Symbol lookup returns empty — the v7 reader doesn't know the SYMS section exists.
- `said admin` subcommands still work because they read FrameMeta from FTOC (core section since v7). MODE / AUDT are unknown to the v7 reader, so it defaults to Portable mode and shows no audit log.

### Backward-incompatible (version bump required)

Changes that require bumping `SAID_VERSION` from 7 to 8 (there are none today):

- Reshaping FTOC entry layout (new required field that breaks the fixed parse)
- Changing SCRM fingerprint width (breaks Hamming distance math)
- Changing BRAN state vector dimensions (brain state becomes meaningless)

When a v8 ships: readers refuse `version > their max`. Writers of v8 cannot produce files readable by v7 readers.

## MODE section — back-compat

MODE was added 2026-04-22 after v7_1 was already in the wild. To avoid a version bump:

- **New writes** always emit the MODE section.
- **Old files** (no MODE section) — readers default to `BrainMode::Portable`.
- **Magic-scan on open** — `data_bytes.windows(4).position(|w| w == b"MODE")`. Found => parse 1 mode byte. Not found => Portable.
- **v7 readers** ignore MODE entirely (they don't know the concept).

Result: zero-risk deployment. Existing brains open without touching them; new writes get the tag; readers old and new stay correct.

Same pattern applied to AUDT (2026-04-22). Magic scan, absent = empty log.

## Migration rules for future sections

When adding a new section:

1. **Prefer magic-scan** unless open-time performance is dominated by scanning. For a 10 MB file, a scan for 4 bytes is ~1 ms — usually fine.
2. **If the section needs header-level access** (hot-path, section is large): bump flag bit and add a new u64 offset slot to the header. Expand `HEADER_SIZE_V7_1` only if you've run out of reserved bits / slots.
3. **Write a graceful-absence path** — the reader must produce correct behavior when the section isn't there. Codify the default (e.g. MODE absent = Portable; AUDT absent = empty log).
4. **Test round-trip on a v7 file** — open, save with the new section, reopen with a v7 reader, confirm it degrades gracefully.
5. **Document the addition** in this page's version matrix AND [`SAID_MVP_PLAN.md`](../../SAID_MVP_PLAN.md)'s status table.

## Reading old files — what to expect

From real SAID-ECHO brains observed in 2026-04:

| File origin | Version | Active frames | Sections present |
|---|---|---|---|
| `willie.said` (pre-mode-gating) | v7_1 | 19,149 | DICT, BLKT, SCRM, BRAN, TRGM, SYMS, FTOC |
| Fresh `said create` post-2026-04-22 | v7_1 | 0 | SCRM, BRAN, MODE, AUDT, FTOC |
| Fresh `said create --mode enterprise` | v7_1 | 0 | SCRM, BRAN, MODE (enterprise byte), AUDT, FTOC |

Both open correctly with current readers. `willie.said` is treated as Portable + no audit history by the current binary.

## Atomic-write guarantee

Every save goes through `state::write_safe(path, bytes)`:

```
1. write bytes to path.tmp
2. fsync path.tmp
3. atomic rename path.tmp → path
4. fsync parent directory
```

If the process crashes between steps 1-3, the original file is untouched. Step 4 ensures the rename is durable. After a crash, `state::read_safe` detects any leftover `.tmp` file (recovery artefact) and cleans up.
